# 自动执行代码审查规则 (Code Audit Trigger Rule)

为了保证项目的交付质量，并确保所有修改都符合反模式规范，所有在此工作区工作的 Agent（包括 Antigravity、Jimmy 等）必须严格执行以下规则：

## 1. 自动触发条件
在出现以下任一场景时，你必须**自动加载并完整运行** `code-audit` 技能：
1. **代码修改完成时**：在你完成任何代码修改、重构或 bug 修复，并准备交付给用户之前；
2. **任务标记为完成前**：在你准备在 `task.md` 中将任务标记为 `[x]`，或者生成 `walkthrough.md` 交付文档之前；
3. **用户明确要求时**：当用户提出包含“审查”、“验收”、“diff审查”、“code review”、“检查残留”等关键词的请求时；

## 2. 审查与验证流程
当你触发上述条件时，必须执行以下步骤：
1. **定位变更**：运行 `git diff` 获取本次的实际代码变更范围；
2. **模式扫描**：调用 `code-audit` 技能，针对 `references/scolv-godot-patterns.md` 中的反模式规则（包括边距硬编码、动态路径拼接等）对所有修改的文件进行全面静态扫描；
3. **核对声明**：将你的“修改声明”与“实际代码”进行逐条交叉比对，绝对不能仅凭直觉或自述认为“已修复”；
4. **输出报告**：在 `<conversation-id>/code_audit_report.md` 中输出审查报告。如果存在任何未完成项，报告判定为 `FAIL`，必须退回继续修复，直至未完成项为 0 且判定为 `PASS` 才能交付。
