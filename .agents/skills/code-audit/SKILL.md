# Code Audit (Habi)

## 核心原则

声明 ≠ 事实。本skill唯一职责：**独立于执行者的自述，对实际diff进行验证**。

- 不以执行者的"总结现在的状态"段落作为审查依据，只读diff本身。
- 执行者声称"已移除X" → 第一步永远是 grep 全库确认 X 真的不存在了，而不是只检查执行者改过的那一处。
- 即使审查结果为"无残留"，也必须显式输出该结论；不能省略"未完成清单"这一环。

## 审查流程

1. **获取变更范围**
   - 拿到 git diff / 变更文件列表 / 执行者声称修改的文件清单。
   - 如果执行者的总结里提到"已数据化/已统一/已切换到X机制"，把这类声明逐条列出来，作为待验证项。

2. **加载规则集**
   - 读取 `references/` 下与本项目相关的反模式规则文件（见下方"项目规则集"）。
   - 规则集是活的文档：审查中新发现的反模式，追加进规则文件，供下次复用。

3. **逐条比对声明 vs 实际**
   - 对每条"已完成"声明，找到对应的验证命令（通常是 grep/正则），跑一遍确认。
   - 不只检查diff里改过的位置——同类问题可能散落在其他未触碰的文件里（"只改了一半"是最常见的失败模式）。

4. **模式扫描**
   - 对diff涉及的文件、以及同类文件（如同目录下的 .gd 文件），跑规则集中的扫描命令。

5. **过滤误报**
   - 只报告能从代码本身验证的问题。
   - 需要运行时上下文才能判断的猜测性问题，标记为 ⚠️ 而非 ❌，不计入"未完成"硬阻断。

6. **输出审查报告**（见下方格式）。

## 输出格式

```
未完成：N 处残留
位置 | 代码 | 问题
...

[若N=0]
扫描完成：无残留。变更范围 X 个文件，规则集 Y 条，全部通过。
```

随后逐条核对执行者的声明：
- 声明1 → ✅ 已验证 / ❌ 部分完成（说明差距）
- 声明2 → ✅ / ❌ / ⚠️ 范围外新发现问题

## 判定门槛

- **PASS**：未完成清单为0，且所有声明均为✅ → 任务进入"完成"状态。
- **FAIL**：任意❌ → 任务退回执行者，附具体位置和验证命令，不进入下一阶段。
- ⚠️ 不阻断流程，但写入备注，留给Hadé/Snow决策。

## 项目规则集

见 `references/scolv-godot-patterns.md` —— ScolV / 东亚海域立志传（Godot/GDScript）常见反模式清单。每次审查中发现新的反模式类别，应追加到此文件。
