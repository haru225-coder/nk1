## 0. 这是什么

东海商游戏已经能跑商、候风、海战、晋升。开局那 98 场剧情是另一套账：玩家在进港口之前就把序章、第一章、第二章点完，选项写下的旗标和效果之后再没有系统读。选「跟阿那走船厂」还是「跟家丁回祠堂」，进港之后是同一局。

P7 要做的事只有一件：**让已经写好的选择，改变港口里看得到的账，并在经营走到占城之后给出终局。** 不新写 98 场正文，不把早期草稿叶接进主循环。

玩家能感知的完成标准：

1. 新游戏只演到岔路口。选海路落入泉州，选举业落入兴化。第一章的寺、账房、码头不再在标题画面后面自动播完。
2. 岔路口和此后每次「有人找你」会改赊贷上限、水粮、舱货、船耐久、发现录或状态栏上的海路/举业倾向。同一选项不能再是空转。
3. 入港最多弹出一条节拍。看过的不再出现。信、复命、礁口各自等玩家真的到了那个港口、到了那一章。
4. 第四章有终局。三条结局由倾向分决定。终局之后沙盒还在，不再有第五章。
5. `scenes.json` 里出现代码不认识的效果键，校验失败。

## 2. 锁定的裁定

实现时按这些做，不再重新开口。

**A. 不重写 98 场正文。** 不改 `body`、`label`、说话人。允许改的是：`sea_path_start` 与 `scholar_path_start` 的 `next`、给归档场加 `legacy: true`、新增 `data/port_beats.json` 与第四章的 `ending` 块。

**B. 不新增 autoload。** 设计第三节提过 `Chronicle`。旗标、名声、发现已经在 `GameState`。P7 只往 `GameState` 加字段，不增加第八个单例，也不改 `project.godot` 的 autoload 顺序。

**C. 两套「章」不要焊死。** `GameState.chapter` 只由 `try_advance_chapter()` 按 `chapters.json` 增加。`apply_effects` 删掉 `"chapter"` 分支。`scenes.json` 的 `chapter` 字符串不参与比较。节拍的 `requires.chapter_at_least` 指经营章。

**D. 海路 / 举业不互斥。** 选举业的人仍然跑商、买船、进博多。倾向只出现在状态栏和终局文案里，不锁港口、不锁船。`chose_sea_first` 只决定开局落点。

**E. 节拍一次入港一条，谈话内部可以走完。** 从节拍的 `entry` 沿 `next` 播放，直到 `next` 是港口 id，或 `next` 落在该节拍的 `stop_before` 里。停下来，回到触发它的港口。同一次入港不接上 `order` 更后的另一条节拍。

**F. 海上三场不插进海图。** `sail` 描写的风涛与 `Voyage` 逐日风涛是同一件事，P7 不播 `sail`。`ryukyu` / `island` / `hakata` 只在玩家已经 `visit_port` 到那个港口之后，作为港口节拍出现，不替代航程，也不白送 `must_visit`。

**G. 效果要么落地，要么校验失败。** 禁止再静默丢弃。数据里出现白名单以外的键，`tools/verify_narrative.py` 非零退出。

**H. 信用为 0 时，赊贷与现在完全一样。** `borrow_limit()` 在 `merchant_credit == 0` 时返回 3000。月息仍是 0.03。`tools/simulate_run.py` 自己的 `DEBT_CEILING = 3000` 不要改——那条脚本不演剧情，信用保持 0。

**I. 终局不关沙盒。** 终局写入旗标 `chronicle_closed`，状态栏改显示结局名。港口节拍不再弹出。经营章停在 4。存档可继续跑商。

**J. 归档场不删除。** 第 3 节名单里的场加 `legacy: true`，正文留着。P7 不给它们做入口。

## 4. 效果白名单

`apply_effects` 返回本次未识别的键数组（空数组表示全部落地）。未识别键 `push_warning` 打出场景 id 与键名。生产路径不弹窗。

| 键 | 落地 | 边界 |
|---|---|---|
| `money` | 现有 `GameState.add_money` | 不变。金钱不低于 0 |
| `fame` | 现有 `GameState.fame += int` | 不低于 0 |
| `days` | 现有 `GameManager.advance_days` | 不变 |
| `flag` | 现有 `set_flag` | 不变 |
| `sea_tendency` | `GameState.sea_tendency += int` | 存储不封顶。状态栏显示整数 |
| `scholar_tendency` | 同上，另一个字段 | 同上 |
| `merchant_credit` | `GameState.merchant_credit += int` | 见 4.1。存储不封顶，消费处钳制 |
| `network` | `GameState.network += int` | 见 4.2 |
| `ledger_note` | `ledger_notes` 追加，已有则忽略 | 只是字符串，P7 没有读取方，除了存档和校验 |
| `supplies` | `Fleet.water` 与 `Fleet.food` **各**加这个整数，再与 0 取大 | 若加上之后水粮占舱超过 `free_capacity` 所允许的增量，两边减到刚好放得下，余量丢弃并写一条日志。不允许把舱位撑成负数空余 |
| `cargo` | 对数组里每个 id，若 `goods.json` 有此 id，`Fleet.add_cargo(id, 1, 0)` | 舱位不够则跳过该 id 并记日志。id 不存在则记日志，不加旗标、不造货。不可交易的账册货允许进舱 |
| `ship` | 旗舰 `durability += int`，钳在 `0 .. max_durability` | 无旗舰则忽略。负值是伤，不是换船 |
| `cargo_loss` | 见 4.3 | 未知 token 只追加为 `ledger_note`，不崩 |
| `discovery` | 先按 `discoveries.json` 的 `name` 全等匹配，再按 `id` 匹配，命中则 `record_discovery` | 未命中记日志。已勘见则 `record_discovery` 现有行为（返回 false）即可 |

删除 `"chapter"` 分支。`verify_narrative.py` 若在 `scenes.json` 看到效果键 `chapter`，失败。

新字段的存档：`GameState.to_dict` / `from_dict` 写入并读取 `sea_tendency`、`scholar_tendency`、`merchant_credit`、`network`、`ledger_notes`、`seen_scenes`。缺键时按 0 或空数组。旧档能读。

状态栏（`Main.update_status_panel`）在名声下面加一行：`海路 {sea_tendency}　举业 {scholar_tendency}`。信用非 0 时在欠债行附近加 `海商信用 {merchant_credit}`。不要为这行新做面板。

### 4.1 赊贷上限

```
borrow_limit = max(0, 3000 + clamp(merchant_credit, -20, 40) * 50 - debt)
```

信用 0 → 上限仍是 3000。信用拉满（消费处 +40）→ 天花板 5000。信用打到消费下限（−20）→ 天花板 2000。月息公式不动。`GameState.DEBT_CEILING` 常量保留为 3000，新公式写在 `borrow_limit()` 里，不要让别处继续硬编码 3000 作为「当前还能借多少」——`borrow()` 已经走 `borrow_limit()`，保持这样。

这条不进入 `simulate_run.py`。脚本里的玩家信用恒为 0，其 `DEBT_CEILING` 与公式在 0 点重合。

### 4.2 人脉与发现概率

`Voyage.roll_day_event` 现有切片（`monsoon_strength` ∈ [0, 1]）：

| 事件 | 宽度 |
|---|---|
| 风涛 | `0.06 + 0.06 * strength`（0.06–0.12） |
| 海盗 | 0.06 |
| 无风 | 0.06 |
| 顺流 | 0.05 |
| 他船 | 0.04 |
| 岸影（发现） | 0.03 |
| 无事 | 其余，盛季风时仍约 0.64 |

人脉只加宽岸影，从无事的尾巴里扣，不动风涛及以前的切片：

```
discovery_extra = clamp(network, 0, 30) / 30.0 * 0.03
```

负人脉不加、不减（避免开局负值把发现从 0.03 抹掉）。满人脉时岸影从 0.03 增到 0.06。盛季风下有事概率合计 ≤ 0.12+0.06+0.06+0.05+0.04+0.06 = 0.39，无事仍过半。

`tools/simulate_run.py` 若自行重写了事件权重，不要把 `discovery_extra` 抄进去。脚本不设 `network`。

### 4.3 `cargo_loss` token

| token | 行为 |
|---|---|
| `qingbai_porcelain_partial_loss` | 若舱内有 `qingbai_porcelain`，`remove_cargo` 其数量的 30%（至少 1，不超过持有量） |
| `tangfang_parcel_water_stain` | 若持有 `tangfang_parcel`，移除 1，并 `ledger_notes` 追加 `parcel_stained` |
| 其他 | `ledger_notes` 追加该 token |

不调用 `lose_cargo_ratio` 去波及全舱。剧情货损只打到 token 点名的那一件。

## 5. 终局

`chapters.json` 第四章对象增加 `ending`。`next_requires` 保持 `null`。`verify_economy.py` 现有逻辑把空的 `next_requires` 当成最终章，额外的 `ending` 键不会撞上它；改完仍要跑一遍确认。

触发：`Main._on_enter_port` 里，若 `chapter == 4` 且 `champa` 已在 `visited_ports` 且 `discoveries_reported.size() >= 3` 且尚未 `chronicle_closed`，弹一次终局，然后 `set_flag("chronicle_closed")`。不新建第五章，不增加 `chapter`。

文案锁定如下，实现时原样写入 JSON，不要改写。

条件与分流：

- 若 `sea_tendency >= scholar_tendency + 4` → `sea`
- 若 `scholar_tendency >= sea_tendency + 4` → `scholar`
- 否则 → `both`

两条都不满足时（含两侧都是 0）走 `both`。这是没怎么点剧情的人的结局，不是错误。

```json
"ending": {
  "title": "占城以后",
  "sea": {
    "title": "海路",
    "text": "占城的码头上有人喊你的船号，喊的不是陈子龙，是那条船的名字。\n\n兴化的祠堂后来怎样，你是在别人的信里知道的。信纸受了潮，字迹糊到只剩一个「榜」字。你把信夹进海图，夹在旧避风澳那一页后面。\n\n北面的消息越来越少。南边的水还深，船还在你手里。"
  },
```
