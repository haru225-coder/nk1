# NK1-P9 任务书 | 发布就绪与首小时体验收口

> 颁布日期：2026-07-13  
> 颁布者：架构主审  
> 执行方式：分批领单、逐批验收；前一批未 PASS，不得把后一批混入同一提交  
> 当前基线：Godot 4.6.3；`2019` 条核心断言全绿；4 组集成自测通过

---

## 0. 任务目的

NK1 已具备可通关主路径、航海/经济/剧情/存档和三结局，当前目标不是扩玩法，而是把“可玩的 Beta”收口为可重复构建、首小时可信、存档可靠的发布候选版。

本期只处理审计确认的发布风险：

1. 共用 KOEI 边框作为 NinePatch 后发生严重拉伸。
2. 标题面板与底部 CommandBar 同时提供导航，“继续”不读档却直跳泉州。
3. 存档直接覆盖正式文件，无原子写入和损坏恢复。
4. 缺少 Windows 导出预设、统一发布验证脚本和 CI。
5. 固定主题样式散落在 GDScript 中，绕过 `main_theme.tres`。
6. `GameState` 混入场景树遍历、过场调度和经济文案职责。

## 1. 分批发布

| 批次 | 任务书路径 | 目标 | 依赖 | 发布闸 |
|---|---|---|---|---|
| P9-A | `docs/P9-A_FIRST_HOUR_UX.md` | 修复边框、标题导航和首小时视觉回归 | 无 | 实机首屏与序章 PASS |

推荐顺序严格为 `P9-A -> P9-B -> P9-C`。P9-B 的存档子任务可并行开发，但不得先于 P9-A 标记“发布就绪”。

## 2. 全局理解与假设

- 产品：Windows 桌面单机 Godot 游戏，不新增联网、账号、遥测或云存档。
- 性能：本期不得新增逐帧资源加载、逐帧 StyleBox 分配或场景树全量扫描。
- 可靠性：任何存档写入失败不得损坏最后一个可读版本。
- 维护：视觉常量以 `assets/main_theme.tres`、`UITheme.gd`、`GameColors.gd` 为来源。
- 所有权：`GameState` 保持兼容门面；新 UI/路由职责进入现有壳层或 system，不扩大全局状态。
- 非目标：不新增港口、剧情、经济规则、战斗玩法、多语言、移动端适配。
- 当前工作区非干净状态；执行者必须保留用户已有改动，不得 reset、checkout 或批量覆盖。

## 3. 全局铁律

1. **先复现再修复**：P9-A 必须保留修复前截图或明确复现记录。
2. **源头修复**：共用资源错误优先修资源本身，不逐屏打补丁。
3. **TDD**：`2019` 断言不可回退；新增逻辑必须有失败路径测试。
4. **视觉验收不能只测“可加载”**：必须实际运行并检查标题、序章对话、港口和地图消费者。
5. **不扩大范围**：发现新玩法问题登记，不在 P9 顺手重构。
6. **提交隔离**：每批单独提交；不得把 P9-C 重构混入 P9-A 热修。
7. **独立复核**：执行者自测后再跑一次完整验证，最终以实际 diff 和运行结果为准。

## 5. 总体验收

- [ ] 标题页只有一套可信导航；“继续”只能来自真实存档槽。
- [ ] 序章对话框、城镇地图、战略地图、战斗/事件/结局外框无拉伸或错位。
- [ ] 写盘中断、临时文件损坏、正式存档损坏时，最后可读存档仍可恢复。
- [ ] `export_presets.cfg` 可从干净工作区生成 Windows 包。
- [ ] CI 与本地发布脚本执行同一组关键验证。
- [ ] 固定视觉样式不再新增散落 override；动态状态样式有明确豁免说明。
- [ ] `GameState` 不再自行查找 CutscenePlayer 或组合经济月报文案。

## 6. Decision Log

| 决策 | 备选 | 采用理由 |
|---|---|---|
| 分 P9-A/B/C 三批 | 单次大提交 | 首小时热修、可靠性和架构清债风险不同，必须可独立回滚 |
| 标题动作只由 TitleScreenController 持有 | 保留双入口并同步 | 双入口已出现语义冲突；单一所有者最小且可验证 |
| 替换共用边框源资源 | 为每个消费者单独调 margin | 当前是源图不适合作 NinePatch，逐屏补丁会继续漂移 |
| 存档采用 temp + 校验 + backup + rename | 继续直接覆盖 | 单机游戏最重要的可靠性底线是“不毁最后可读存档” |
| P9-C 只抽离已确认越界职责 | 全面重写 GameState | 保持兼容门面，控制回归面，避免把发布期变成重构期 |
