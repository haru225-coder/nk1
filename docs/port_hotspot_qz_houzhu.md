# 后渚码头场景热区试点设计

范围：仅 `qz_houzhu`。保留旧工席名单作为切换页和回退页。

## 0. 玩家怎么玩（8 行内）

进后渚先见码头底图，不自动展开整段 `description`。  
底图上有五处淡墨点，落在盐包、货箱、番船、梢工和收盐跳板附近。  
悬停或键盘聚焦只显示对象名；点击后，右侧短讯层出一句旁白或两句对话。  
收盐、卖象牙在短讯下接原工席确认条；确认后才走原 Book，点墨点不直接成交。  
`qz_houzhu_fast` 未解锁时也能点开，但只提示先请梢工，不提前执行。  
顶栏「工席名单」切回旧卡片页；点「场景」返回，保留当前热区和短讯。  
「回港口」沿用旧入口；Esc 先关短讯，再按原退回规则处理。  
传闻和一次性委托办完后，墨点留已闻、已办记号，不重复发结果。

## 1. 画面结构

### 分层

| 层 | 内容 | 规则 |
|---|---|---|
| 底图层 | 后渚现有区页背景或既有码头底图 | 原图适配显示。不重画，不补人物立绘。 |
| 热区层 | 五个透明点击区、墨点、对象名 | 坐标相对实际底图显示矩形。原点在左上，`x` 向右，`y` 向下。避开黑边。 |
| 短讯层 | 一句旁白、两句对话、原工席确认条 | 宽屏放右侧。窄屏可落到底部。打开后不盖住所选墨点。 |
| 顶栏 | 区名、「场景／工席名单」、「回港口」 | 沿用区页导航。不另建页面栈。 |

初始短讯只取原文首句：“后渚是泉州出洋的码头。”  
长描述仍留在旧名单页。场景页不先堵一段文字。

### 复用与新建

新建 `scripts/ui/DistrictHotspotView.gd`。

- 负责底图、热区和短讯的排布。
- 负责归一化坐标换算、点击命中、 hover、键盘 focus。
- 点击后只抛出热区 `id`。
- 不读价格，不判断解锁，不直接写 flag。
- 不直接调用 Book。

复用现有能力：

| 现有位置 | 复用内容 |
|---|---|
| `Main` | 当前区进入、页面切换、退回港口的既有接入点。 |
| `UiTheme` | 字体、间距、面板、按钮、焦点框及既有墨色状态。 |
| `TitleMapExplorer.gd` | 底图加墨点、侧栏短注的交互方式，以及 normal／hover／focus／pressed／visited／selected 的表现约定。 |
| `DistrictPage.gd` | 区数据读取、interaction 查找、条件判断、原确认流程和旧卡片页。 |
| 原 Book 及互动处理器 | 买卖、传闻、favour、once 的实际执行和结果。 |

`DistrictPage.gd` 是试点控制器。它决定是否显示场景页，并把热区 `id` 交回原互动流程。  
`DistrictHotspotView.gd` 只做场景表现和输入。  
本试点不为了共用而顺手重构首页。首页已有可复用样式就直接用。

## 2. 热区表（后渚全部 interactions）

坐标为排布估值。实现时按底图避让船体、人物和顶栏。  
牙行货箱若在原图中不明显，只移动墨点，不补画摊位。

| id | 画面上像什么 | 坐标 `(x,y)` | `kind` | 点开后的短讯形态 | 数据与执行 |
|---|---|---:|---|---|---|
| `qz_houzhu_salt` | 石岸旁的盐包和挑担脚夫。 | `(0.22,0.66)` | `goods` | 工席确认条：「收海盐」。保留原数量、价格和确认／取消。 | 确认后走原 `buy` 与 Book。热区本身不改货物、银钱或价格。 |
| `qz_houzhu_ivory` | 近岸货箱上的牙行货单。 | `(0.73,0.69)` | `goods` | 工席确认条：「出手象牙」。沿用原出售确认。 | 确认后走原 `sell` 与 Book。库存和成交结果仍由原逻辑写。 |
| `qz_houzhu_rumor` | 番船船楼边，可向船客问话。 | `(0.72,0.31)` | `ship` | 对话两句：先给原传闻内容，再用一句短问或收束结束。 | 走原 `rumor`。奖励、限制和已听记录不由热区另算。 |
| `qz_houzhu_pilot` | 跳板旁等活的熟港梢工。 | `(0.48,0.53)` | `person` | 对话两句；需要确认时接原 favour 确认条。 | 走原 favour。成功后仍由原逻辑设置 `qz_houzhu_pilot`。 |
| `qz_houzhu_fast` | 跳板下替商船收盐的脚夫队列。 | `(0.40,0.77)` | `person` | 已解锁时为工席确认条：「托梢工收盐」；未解锁时为旁白一句，说明先请梢工。 | 条件和 once 均走原逻辑。未满足 flag 不执行；已办后只回看结果。 |

短讯层规则：

- 旁白最多一句。对话最多两句。
- 工席确认条不重复长描述。
- 买卖失败时，在确认条位置显示原失败原因。
- 切换短讯不自动执行互动。
- 原互动没有文案时，先用其名称和一句对象短注，不在 `hotspots` 内复制经济配置。

## 3. 数据增量

需要加可选的区字段：

`hotspots:[{id,x,y,kind}]`

放在 `districts[]` 内，与 `interactions` 同级。

| 字段 | 用途 | 约束 |
|---|---|---|
| `id` | 对应一个现有 interaction | 必须能查到。不可重复。 |
| `x`、`y` | 底图归一化坐标 | 均为 `0–1`。只负责摆位置。 |
| `kind` | 辅助说明对象类别 | 试点用 `person／ship／goods／place`。不决定互动类型。 |

`hotspots` 不放价格、货物、奖励、条件、flag 或 once。  
互动执行仍以 `interactions` 为准。

### 旧字段保留

- `interactions[].id`、`type` 全保留。
- 买卖的货物、数量、价格及 Book 参数全保留。
- 传闻文本和原结果配置全保留。
- favour 的代价、条件和结果全保留。
- `qz_houzhu_fast` 对 `qz_houzhu_pilot` 的依赖不变。
- once 和现有存档状态不变。
- `description` 保留给旧名单页、回退和无障碍文本。
- 区名、区 id 和其他区数据不动。

### 回退

- 没有 `hotspots`，或数组为空：直接显示旧卡片页。
- 坐标缺失、越界、`id` 重复或找不到 interaction：整个区回退旧卡片页，并记数据错误。
- 热区未覆盖该区全部 interactions：整个区回退，避免少掉可执行事项。
- 其他 71 个区没有坐标时，行为完全不变。
- 即使热区数据有效，也保留「工席名单」手動入口。
- `visited`、当前短讯等纯界面状态不写入 `districts.json`，不新增经济存档字段。

## 4. 状态与反馈

只用首页墨点和 `UiTheme` 已有色。  
不新增锁定的灰色、成功绿色或警告红色。

| 状态 | 表现 | 使用时机 |
|---|---|---|
| `normal` | 首页普通淡墨点。无对象名长驻。 | 未指向、未选中。 |
| `hover` | 沿用首页 hover 强调，并显示短对象名。 | 鼠标移入。 |
| `focus` | 沿用 `UiTheme` 焦点表现，同时显示对象名。 | 键盘或手柄聚焦。 |
| `pressed` | 沿用首页 pressed 短暂反馈。 | 按下到释放之间。 |
| `visited` | 沿用首页 visited 的低权重记号。 | 本次界面会话中点开过。只表示看过，不表示完成。 |
| `selected` | 当前墨点保持选中记号，短讯层同步展开。 | 当前查看对象。 |

`visited` 可与 `selected` 叠加。输入态优先显示。  
视觉墨点可以小，实际点击区要按透明热区处理。

### 办完后的记号

- **买卖成功**：短讯层显示原 Book 成交结果。墨点记为 `visited`。不打完成勾，不置灰，仍可再次买卖。
- **买卖失败**：保留当前选择和确认条。显示原失败原因。不改经济状态。
- **传闻已听**：墨点保持 `visited`，对象短注加「已闻」。可重看文本。是否可重复领取结果仍由原逻辑决定。
- **once 已办**：墨点保留并标「已办」。点击只回看结果，不再次执行。
- **fast 未解锁**：不加新颜色。点开显示条件短注。解锁后按原状态恢复可执行。
- **重复打开场景**：当前会话可保留选择。离开区后允许清掉纯 UI 的 `visited`，不能拿它替代存档。

键盘确认与点击等价。Esc 先取消确认或关闭短讯，不直接吞掉「回港口」。
