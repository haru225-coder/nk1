## 二、六个决策点（代拟 D1–D6）

每条的写法：现状 → 选项（系统影响分五项：数据结构 / 数值 / UI / 存档 schema / 文案量）→ 在代码里落在哪 → 推荐项 → 最小可行实现的工作量与风险。
工作量按本仓 lane 的粒度算：「一刀」约等于一个 lane（改一处系统 + 门禁 + 探针）。

### D1　伙伴和「职事」是什么关系（系统骨架）

**现状**：唯一有名有姓、能雇的人是 `Crew` 的 18 名职事；要人和市井 26 人只出现在剧情和人物志里。

| 选项 | 数据结构 | 数值 | UI | 存档 | 文案 |
|---|---|---|---|---|---|
| **A 伙伴就是职事扩编**：40 人全进 `crew.json` 的 `candidates`，每人配一个职事 | `candidates` 从 18 人扩到约 40 人，另 22 人要指定 `role`、`level`、`wage`、`port` | 仍是一职一人，加成公式不动；但阿那、林阿舶这些要人要和吴针们抢那 6 个位子 | `_setup_hiring` 原样可用 | 不变 | 22 份候选 `bio` 与职事旁注 |
| **B 另起一套 `Companions` autoload，与 `Crew` 并列** | 新建 `data/companions.json` 和新单例 | 新开一条加成通道，`verify_economy` 要照样再镜像一遍 | 新页面或新浮页 | 新分区 `companions`，schema 升到 3，`_check_partitions` 同步改 | 大 |
| **C 分两层**：`Crew` 还管 6 个职事位（加成），伙伴是「人」这一层。伙伴可以补职事位，也可以不任职、只随船（管剧情、白刃、事件） | `crew.json` 不动；新加一张表，经 `characters.json` 已有的 `sources.crew_id` / `npc_id` 桥接 | 职事加成不叠加，`verify_economy` 各断言原样有效 | 酒馆页照旧；船籍簿加一栏「随船」 | `GameState` 加一个伙伴 id 数组，迁移时缺省为 `[]` | 中 |

- **落点**：`Crew.gd:12/41/61`、`Main._setup_hiring`（`Main.gd:2509`）、`LedgerPage.gd:252`、`SaveLoad.gd:25/203`
- **推荐 C**。理由：① 6 条加成公式和 `verify_economy` 那几条护栏一行都不用动；② 林华、阿那、净海这类「剧情里的人」不必硬安一个职事，就能以随船身份上船，林华伏笔（1.5）也正好有了落脚处；③ 与 P2「坐地代理不走 `Crew`」的做法一致，不污染 `check_symbols` 的职事契约段。
- **工作量**：A 一刀；B 三刀以上；C 两刀（第一刀数据表加存档字段加船籍簿显示，第二刀剧情入口）。
- **风险**：A 会让要人变成「数值件」，冲淡人物；B 会有两套雇佣规矩，玩家要学两遍，门禁也要写两份镜像；C 的「随船」位若日后被要求也给加成，就会滑回 B。

**现状**：职事至多 6 人（一职一人，`Crew.hire` 在 `Crew.gd:67` 拦截）；普通水手按船种有上下限（`ship_crew_max`）。

- **风险**：职衔主要靠跑商涨名声，名额会随跑商节奏放开，而不是随剧情节奏；如果想要「第三章才见到某人」，D6 另外要用章节或旗标卡。

- **推荐 A + D**。理由：公式和护栏都不动；14 种特长现成就有，拿来卡剧情分支，能让「船上带了谁」变得要紧，又不用重新配数值。D 只需要给 L1b 加一个运行时读 `traits` 的入口。
- **工作量**：A 为 0；D 一刀（门槛函数 + L1b 登记 + 一两个示范分支 + 门禁断言）；B 一刀，但要改存档；C 两刀以上。
- **风险**：C 最大，经济平衡要重做；B 会和旧档的快照打架；D 的风险在文案量，门槛写多了维护不过来。

### D4　关系怎么记：好感、忠诚，还是只有契约

**现状**：没有逐人的关系数值。离心只来自全局的欠饷（`Crew.unpaid_months`，三个月就走一人）和全局士气；P2 设计把「NPC 好感度」列进了不做清单；40 人之间的 57 条关系只用于展示。

| 选项 | 数据结构 | 数值 | UI | 存档 | 文案 |
|---|---|---|---|---|---|
| **A 纯契约**：沿用月俸和欠饷 | 无 | 不变 | 不变 | 不变 | 无 |
| **B 每人一个忠诚值 0–100** | `{id: int}` | 要定升降规则、阈值事件，还要写一条新的模拟验算 | 每张卡加一个刻度 | 新字典，schema +1 | 每档阈值一段台词 |
| **C 用事件旗标记离合**：入伙、交心、离心、离队都由剧情选项 `set_flag` 决定，不存数值 | 沿用 `GameState.flags` | 不变 | 人物志里多一段可见条件 | 不变（旗标本来就存档，还经过 `SaveLoad._normalise_flags` 清洗）| 每人 1–3 个节点 |
| **D 关系网驱动**：同船的两个人有相亲或相克，影响士气 | 用 `relations` 现成的边，另加一个极性字段 | 士气多出一个来源 | 船籍簿显示同船关系 | 不变（从在船名单推出）| 57 条边各要一句 |

- **落点**：`Crew.pay_wages`（`Crew.gd:156`）、`GameState.flags` / `set_flag`（`GameState.gd:583`）、`SaveLoad._normalise_flags`（`SaveLoad.gd:114`）、`characters_codex.json` 分段可见条件（`"c2"`…`"end"`）
- **推荐 C 加 A**（月俸照发，关系走剧情旗标）。理由：零新数值，不碰 P2 不做清单那一条；旗标本来就进存档，还有硬化；人物志的分段可见机制可以直接拿来「按交情放出身世」。
- **工作量**：C 一刀（给剧情节点加旗标约定 + 离队处理 + 人物志分段），文案另算；B 两刀，外加一份模拟验算；D 两刀。
- **风险**：C 的离合完全靠剧本，没有剧情节点的人（比如 18 名职事里的大多数）等于没有关系线；B 很容易做成「送礼刷好感」，跟本作的纪实口吻不合。

### D5　离队、死亡，以及史实人物的结局

**现状**：离队有三条路：辞退、欠饷三月、跳年每年 12%；没有死亡。40 人里 `historical == true` 的有陈瓒、林华、黄恮、黄氏、姻家使者（外加主角）。林华史实上 1276 年出侦即降；终局设计的原话是「史实不变，他仍然降」，而这条伏笔现在是死的（1.5）。

| 选项 | 数据结构 | 数值 | UI | 存档 | 文案 |
|---|---|---|---|---|---|
| **A 史实锁死**：到了史实时间点就强制离队，并演一段（林华 1276-12 降元）| 每人一个 `fate`（年月 + 去向）| 无 | 离队时弹一张通告或过场 | 不变（到点删名单 + 记旗标）| 每个史实人物一段 |
| **B 可改写**：交情够深，史实人物可以不走史实的路 | 同 A，另加改写条件 | 无 | 同 A | 同 A | 每人两段（照走一段、改写一段），终局也要跟着分叉 |
| **C 史实人物不入伙**：只让 34 名虚构人物上船，史实人物只作剧情 NPC | 无 | 无 | 无 | 无 | 最少 |

另有一个子问题：跳年流失（`GameManager.gd:231`）对伙伴豁不豁免？不豁免的话，玩家花十年培养的人会随机消失。

- **落点**：`Main._siege_lin_hua`（`Main.gd:5309–5312`）、`GameState.crew_history` / `record_crew`（`GameState.gd:576`）、`GameManager.skip_years`（`GameManager.gd:202`、`:231–235`）、`data/npcs.json` 林华条
- **推荐 A，伙伴不吃跳年流失**。理由：A 与终局设计「知道历史也改不了历史」一致，还能顺手修好林华的死分支：只要他入伙时写进 `crew_history`（或新的伙伴历史），就能接上；B 会把终局五个结局都拖进分叉。跳年流失对「有名有姓、有剧情的人」随机生效，损失感大于趣味，建议只对无剧情的职事生效。
- **工作量**：A 一刀（`fate` 表 + 月结检查 + 通告 + 林华接线）；「伙伴不吃跳年流失」半刀。**林华死分支可以不等拍板先修**：在 `crew.json` 加一个 `lin_hua` 候选即可，这是 `npcs.json` 本来就写好的计划。算作单独一刀，是否先做由 Snow 定（Q8）。
- **风险**：A 要守住「到点离队」和 `Calendar` 跳年的顺序（跳年会一次跨过这个时间点）；B 的文案量和终局分叉都会翻倍。

### D6　从哪里招、什么时候开放

**现状**：只有酒馆一个入口（`Main._setup_hiring` → `Crew.candidates_at`），过滤条件是港口、章节、旗标；18 人里 ch1 就开放 11 人，第三章前全部开放。`十三年空洞` 第一节把「职事招满太早」列为结构问题。

| 选项 | 数据结构 | 数值 | UI | 存档 | 文案 |
|---|---|---|---|---|---|
| **A 全走酒馆名册**（扩 `candidates_at`）| 候选加字段 | 无 | 不变 | 不变 | 每人一份 bio |
| **B 全走剧情入伙**：`scenes.json` / `port_beats.json` 的选项 `set_flag` 之后直接入伙 | 选项加 `join` 动作 | 无 | 剧情页里出入伙提示 | 不变 | 每人一个入伙场景 |
| **C 混合**：职事走酒馆，要人和市井走剧情 | A 与 B 各做一部分 | 无 | 两处都有 | 不变 | 中 |

- **落点**：`Crew.candidates_at`（`Crew.gd:41`）、`GameState.is_chapter_reached` / `flag_requirement_met`、`Main._setup_story_hooks`（`Main.gd:2473`）、`data/scenes.json` 的选项结构

- **工作量**：D 半刀；C 里剧情入伙那部分一刀，外加每人一个入伙节点的文案。
