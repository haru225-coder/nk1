# 侧车口径：哪些 `.uid` / `.import` 必须入库，哪些不许带

门禁：`python3 tools/check_sidecars.py`（`docs/GATES.md` §三.17；脚本头部注释与本表同口径）。lane ag 立的规则，lane ag2 收口。

## 为什么要入库

Godot 4 给 `.gd` / `.gdshader` 生成 `<文件>.uid`，给可导入素材生成 `<素材>.import`（里面有 uid 和导入参数）。`.tscn` / `.tres` 的 `ext_resource` 按 `uid://` 引用这些 uid。侧车不入库的话，别处 clone 下来重新生成，素材的 `.import` 会拿到随机 uid，场景引用只能退回按 path 兜底，导入参数也会丢。`.gitignore` 故意不忽略侧车（Lane Z4 注释）。

## 同车规则（每个 lane 照做，不再靠补缺小片扫尾）

**新增源文件的 commit 必须同车带上它的侧车**：新 `.gd` / `.gdshader` → `<文件>.uid`，新素材 → `<素材>.import`，挪 / 删源文件 → 侧车跟着挪 / 删（`git mv` 连侧车一起）。步骤：

1. 源文件写好后跑一次编辑器让它生成侧车：`godot --headless --editor --path . --quit`（别手写 uid）。
2. `git add -- <源文件> <源文件>.uid`（显式 pathspec，只带本 lane 新增的那几份）。
3. `python3 tools/check_sidecars.py`：本 lane 不得新增 FAIL；提交前是几项红，提交后不能更多。
4. 源文件和侧车进**同一个** commit。

指令或 brief 里的「无 `*.uid` / `*.import`」「跳过 `*.uid`」只指下表写着**不入库**的几行（别人的未跟踪侧车、编辑器顺手改写的已跟踪侧车、生成物），**不**豁免本 lane 新增源文件的侧车。两者真冲突时按本规则带上，并在 SETTLED 行写明。

来由：ms2（`ChapterSheet.gd`）、g2（`gate_report.gd`）、main4（`TavernPage.gd`）三次新增源文件都按「跳过 *.uid」没带侧车，check_sidecars 转红，分别由 uid1 / uid2 / uid3 补缺小片扫尾。

## 判定表

| 情形 | 入库？ | 谁、怎么提交 | 门禁怎么判 |
|---|---|---|---|
| 本 lane **新增** `.gd` / `.gdshader` → `<文件>.uid` | **必须** | 同一 commit 带上；让编辑器扫一遍生成（`godot --headless --editor --path . --quit`），别手写 | 缺 → `缺已跟踪的 X.uid` |
| 本 lane **新增**素材（图 / 音 / 字体 / 模型 / csv）→ `<素材>.import` | **必须** | 同一 commit 带上 | 缺 → `缺已跟踪的 X.import` |
| 本 lane **有意**改导入参数、换源图 → `.import` 改动 | **必须** | 同一 commit 带上 | 不带 → 工作树漂移 |
| 挪 / 删源文件 → 旧侧车 | 跟着挪 / 删 | 同一 commit；挪完跑一次编辑器让它重导，再提交重写过的 `.import` | 只挪不重导 → `内容漂移：source_file…` / 产物名哈希对不上；只删源 → `只提侧车不提源` |
| 拷一份素材 | 只拷源文件 | 别连侧车一起拷，让编辑器生成新侧车 | 连侧车拷 → uid 重复 + 内容漂移 |
| 编辑器**顺手改写**的已跟踪侧车（源文件和参数都没动） | **不入库** | `git checkout -- <侧车>` 还原；成片出现说明基线变了（见下文 terrain） | 工作树漂移 |
| 别的 lane 留在共享工作树里的**未跟踪**侧车 | **不入库** | 归源文件所属 lane，或开一个补缺小片（显式 pathspec 只加那几份） | 不查未跟踪文件；源文件已跟踪时报成「缺 .uid」，算到源文件那一方头上 |
| 源文件那一类 Godot 根本不生成的侧车（`.tscn.uid`、`.json.import` 等） | **不入库** | 删掉 | `多余侧车` |
| `.godot/`（导入产物 `*.ctex`、`uid_cache.bin`、editor 缓存）、`*.translation` | **不入库** | `.gitignore` 已忽略 | 不查 |
| `.gdignore` 目录（如 `tools/art_src/`）与 `.` 开头路径下的文件 | 无侧车 | Godot 不扫这些地方 | 不查 |

旧口径「提交时跳过 `*.uid` / `*.import`」的真实边界是表里写着**不入库**的那几行：别人的未跟踪侧车、编辑器顺手改写的侧车、生成物。它**不**包括本 lane 新增源文件对应的侧车，那一份必须同 commit 带上（lane ag 已把 COORDINATION / opus-queue 的规矩改成这个意思）。

## 一致性（门禁第 5–7 条）

- `.uid` 必须是一行 `uid://[0-9a-z]+`。
- `.import` 的 `[deps] source_file` 必须是 `res://<自身源文件>`；`.godot/imported/` 下的产物名必须是 `<文件名>-<md5("res://路径")>.…`，挪过或拷过没重导，这两项会对不上。
- uid 全仓唯一（`.uid`、`.import`、`.tscn` / `.tres` 头）；`ext_resource` 写了 `uid=` 的，必须等于目标侧车里的 uid。
- 已跟踪侧车在工作树里被改写或删掉，报「工作树漂移」（`--index-only` 跳过这一项，只看索引）。

## VRAM 纹理基线与 `terrain_4096.png.import` 可移植性（lane ag2 实测）

库里只有 `assets/map/terrain_4096.png` 一张图用 `compress/mode=2`（VRAM 压缩），`[remap]` 的写法取决于导入机能出哪几种 VRAM 格式。**基线 = 桌面 x86_64 的 `s3tc_bptc` 一种**，也就是 `6020aba` 提交的形态：`path.s3tc` + `imported_formats: ["s3tc_bptc"]` + `vram_texture: true`。

跨版本实测：干净 worktree（基 `d906d68`，全新 `.godot/`），`godot --headless --editor --path . --quit` 全量导入后看 `git status`：

| Godot（linux x86_64 官方包） | rc | 被改写的已跟踪文件 | 生成的 10 份缺失 `.uid` |
|---|---|---|---|
| 4.5.2-stable | 0 | 0 | 与 4.6.3 逐字相同 |
| 4.6.2-stable | 0 | 0 | 同上 |
| **4.6.3-stable（项目现用）** | 0 | 0 | 基准 |
| 4.7.2-stable | 0 | 0 | 同上 |

所以在 x86 桌面上换版本（4.5.2–4.7.2）不会再弄脏 terrain，也不会弄脏其余 262 份 `.import`。`.gd` 的 uid 按路径确定，跨版本不变。

会变脏的是**平台**：ARM 主机（Apple Silicon / ARM Linux）、有移动端导出预设、或 project.godot 打开了 `rendering/textures/vram_compression/import_etc2_astc` 时，导入会多出或换成 `etc2_astc` 分支。实测在 x86 上打开 `import_etc2_astc=true` 后，terrain 写成 `path.s3tc` + `path.etc2`，`imported_formats: ["s3tc_bptc", "etc2_astc"]`，再跑一次保持稳定。但把这份双格式 `.import` 提交上去、同时关掉设置的话，一旦清掉 `.godot/imported/` 重导，就退回只有 s3tc。也就是说，只提交双格式 `.import`、不改 project.godot，是**不稳定**的。

处置（门禁基线，不加忽略规则）：
1. 门禁把 VRAM 纹理的 `imported_formats` 钉在基线：project.godot 没开 etc2 时必须**恰好** `["s3tc_bptc"]`，`path.*` / `dest_files` 与之一致。ARM 机器写出的 etc2 形态、只提交一半的双格式形态、908b46f 那种 `compress/mode=2` 配 `vram_texture:false` 的自相矛盾形态，入库一律判红。第二种形态进不了库。
2. 在 ARM 机器上跑编辑器之后，本地出现的 terrain 改写会被「工作树漂移」点名。处置是 `git checkout -- assets/map/terrain_4096.png.import`，不要提交。
3. 真要支持 ARM / 移动端时，一次性切换：在 project.godot `[rendering]` 加 `textures/vram_compression/import_etc2_astc=true`，重导后把双格式 `.import` 和 project.godot 放进同一个 commit。门禁读索引里的 project.godot，基线会自动变成两种格式。代价是多一份 etc2 产物（导入时间和 `.godot/` 体积），桌面导出不受影响。另一条路是把这张图改成 `compress/mode=0/1`（不走 VRAM），但显存占用会变。两条路都由 Snow 拍板。
4. 如果以后升级到某个会改写 `[params]` 的 Godot 版本（本次 4.5.2–4.7.2 实测都没有），就当作一次「升级引擎」lane 来做：`config/features` 与全部被改写的 `.import` 放进同一个 commit，别让它们零散漂在各 lane 的工作树里。

## 免删口径：工位里「不算未落盘改动」的已跟踪等价侧车（wt5 立，w39-k4 量具等价定案）

某路径 **main 已经跟踪**，且 worktree 里的未跟踪同名侧车满足下列条件之一，这种侧车**不算未落盘改动**（取证后随工位核销即可，无需补缺小片、不入任何 commit）：

- **(a)** 内容与 main 已跟踪版本**字节相同**；或
- **(b)** 内容不同，但该值在 main 上**没有任何地方引用**（`git grep -F <uid> main` = 0；`.import` 改写侧以与 main 现文件字节相同为准入 (a) 同型）。

判档恒等式（wt5 :43 要件，wave39-k4 三节量差法复核钉死）：wave19-wt5 案 **(a) 44 / (b) 10 / `.import` 3 = 57**，支计要件 6/7/8/10/12/12 闭式不动点；要件帧任何下波复跑不得破，破即要件漂移、按悬案重开。

**本法附则（w39-k4 定）**：工位焚后，判档具现化预演 = 量具等价——判据行现窗 0 ≠ 简注差，差额三节立档（①差额全额历史解释；②全 git 可达面扫描排除迁移；③HEAD/取证要件仍在 → 判档条目合成工件、确定性替位（(b) 类 `uid://<sha1(案-支-路径)[:13]>`，逐件证 grep-F=0 且 ≠ main blob）后量具语义仍立）。免删 = 不建账、不回帧。

来由：wave19 lane wt5 九工位 57 名（取证档 uid-diff-refs.txt 等三卷，已随档焚；判档在 `lane-wt5-sidecar-policy-worktree-2.md`）；wave39-k4 以三节量差法在工件已焚域结案（57 名实帧表 lista57 在仓外加录档）；本口径 wave20-39 全程经得起在跑片复用（w39-k1 夺得 (a)/(b) 名词作判据、w38-k2 双帧 glock compile 全绿背书 bad 不动）。
