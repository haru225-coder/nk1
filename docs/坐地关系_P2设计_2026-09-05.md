## 一、一句话与设计目标

**在同一个港口反复做生意，会在那里长出关系；关系到了火候，这个港口就开始给你别人没有的价钱、别人没有的仓、别人没有的人。**

对应《十三年空洞》诊断：1256–1268 这十三年里，玩家手上除了「钱变多」没有第二个会增长的东西。钱在 1255 年内就能到三万，之后每一趟航行都只是同一个动作的重复。坐地关系要提供的是**第二条增长曲线**——它慢、它按港口分开长、它在跳年时会因为疏于经营而回落，因此它值得你年复一年地回到同一个港。

三条硬约束（对应 Snow 的三条铁律）：

1. **不做成文字游戏**：坐地关系只由数值、入口卡换皮、价格公式承载。全篇不新增线性幕串，文案每处不超过两句。
2. **历史不是菜单**：泉州蕃坊的关系再好，1276 年蒲寿庚照样降元，你的仓照样在城破那天空掉。关系改变的是你手里有什么，不是历史往哪走。
3. **数据里写的键代码必须接住**：新增的 `factions`（ports.json）与 `standing`（effects 键）都要在同一次提交里接上读取端，并进 `verify_story_data.py`。

### 2.2 存档字段

`scripts/GameState.gd` 新增三个字典（放在 `merchant_credit` / `network` / `port_bans` 那一组，即 L32–37 附近）：

### 2.3 什么不入存档

`Economy.war_status()`（`Economy.gd:164–176`）是纯 Calendar 函数、不入档、读档随历法自然复原——这是本仓最漂亮的一处设计。坐地关系**不能**照抄：它是玩家行为的账，必须存。

但**由 standing 派生的东西一律不存**，全部做成纯函数：

- `GameState.standing_of(port_id, faction) -> int`
- `GameState.has_privilege(port_id, faction, threshold) -> bool`
- `Economy._effective_tariff(port_id)` 里的折扣系数
- 仓储容量 `GameState.warehouse_cap(port_id)`

存的只有三个原始字典，其余都是它们的函数。这样 P6 调阈值时不会留下一批与新公式不符的旧档。

## 三、累积与衰减

### 3.1 累积来源

| 来源 | 加给谁 | 数值 | 插入点 |
|---|---|---|---|
| 入港 | 该港全部派系 | 各 +1，同港同月只记一次 | `Main._on_enter_port()`（L2217–2225），紧跟 `GameState.visit_port()` |
| 成交额 | 按货物分派（见下） | 每 1000 钱 +1 | `Main._on_buy()`（L474）与 `_on_sell()`（L519），成交后 |
| 领货引 | 牙行 | +2；不领而出港 −1 | `GameState.apply_for_permit()` / `customs_inspection()`（L525–572） |
| 捐施 | 寺院 | 每 500 钱 +1 | 新「寺院」设施页 |
| 战况站队 | 见第七节 | 泉州蕃坊 +25 / −20 | `Main._setup_quanzhou_standoff()`（L584–650） |

成交额按货物归派系：

- **蕃坊**：`aromatic_medicine`、`pepper`、`ivory`、`coral`、`sappanwood`（南货五种，`goods.json` 里 `historical_note` 已点名蕃坊/抽解）
- **寺院**：`sutra_scrolls`、`tea`、`korean_paper`（经卷、茶、高丽纸；`goods.json` 已注开元寺、寺社）
- **牙行**：其余全部货物

若该港没有对应派系，这笔成交额落到牙行；若牙行也没有（澎湖/流求/南九州），什么也不加。

**上限与冷却**（防刷，第九节还会再列）：

- 单次交易至多 +4
- 单港单派系单月至多 +8
- 入港加成同港同月一次

按最激进的刷法算：一个月内在泉州反复买卖，单派系至多 +8，三派系 +24，加入港 +3 = 27。从 0 到 60（可雇代理）至少要三个月的**连续满负荷**经营，且钱要真的过手。这不是一趟航行能拿到的东西——正是设计目的。

### 3.2 衰减

**按月自然衰减**：`Economy.on_month_changed()`（L199–224）已经是月结的挂钩点，在它旁边加 `GameState.decay_standing()`：

- 该月在该港有过成交 → 不衰减
- 否则每个 `> 0` 的 standing `−1`
- 有坐地代理的港 → 全部派系不衰减

**跳年衰减**：`GameManager.skip_years()`（L93–134）是唯一一处「时间大段过去」的结算函数，现有代价是船况年折 8%、水手年离 12%、士气压 65、行情全部重置为 1.0。坐地关系加进去：

- 无代理的港：每年 `−12`（与水手年离同一量级，同一种「你不在，人就散了」的语义）
- 有代理的港：不衰减，另按第五节做一次性结算

注意 `skip_years` 是**先把日子真的走完再结算代价**的（新闻、月结、行情回归照常）。所以月衰减在跳年期间已经跑过一遍了，年衰减是**额外**的。两者叠加后 4 年跳年 = 月衰减 48 次 + 年衰减 48，会把任何未维持的 standing 归零。这是对的：不派人守着，九年之后泉州没人记得你。

## 四、特权表

阈值统一取 **20 / 40 / 60 / 85**。60 是「可雇坐地代理」的共同门槛。

### 4.1 牙行 → 抽解折扣 + 优先货源

牙人替你走单、替你留货。这是四项交付里的「抽解折扣」与「优先货源」。

| standing | 特权 | 插入点 |
|---|---|---|
| 20 | 抽解 ×0.95 | `Economy._effective_tariff()`（L98–103） |
| 40 | 该港 `origin` 货买价 −5%（先给熟人开秤） | `Economy.price_at_rate()`（L111–118） |
| 60 | 抽解 ×0.85；**可雇坐地代理** | 同上 / `Main._setup_yamen()`（L539–579） |
| 85 | 抽解 ×0.75 | 同上 |

`_effective_tariff` 现在长这样（L98–103），已经有一处**按港打折的先例**，坐地折扣照它的形状加一行即可：

```gdscript
func _effective_tariff(port_id: String = "") -> float:
    var war_mul: float = WAR_TARIFF.get(war_status(port_id), 1.0) if port_id != "" else 1.0
    # 对峙期站了蒲家：泉州抽解永久八折——「都是一家人」
    if port_id == "quanzhou" and GameState.has_flag("sided_pu"):
        war_mul *= 0.8
    return tariff_rate * Crew.trade_cost_factor() * war_mul
```

**「优先货源」本期只做「更低进价」，不做「多出一种货」。** 后者要动 `Economy.goods_at()`，会撞上 `verify_economy.py` 的航线与死港校验，收益不匹配。留给 P4。

### 4.2 蕃坊 → 赊贷 + 南货优惠

| standing | 特权 | 插入点 |
|---|---|---|
| 20 | 蕃商赊贷上限 ×1.5 | `GameState.borrow_limit()`（`Main.gd:1030` 调用处可见） |
| 40 | 南货五种买价 −8% | `Economy.price_at_rate()` |
| 60 | 行佣 5% → 3%；**可雇坐地代理** | `Economy._effective_broker()` |
| 85 | 赊贷月息 ×0.5 | `GameState.accrue_interest()`（`GameManager.gd:64–78` 月结调用） |

`_effective_broker()`（`Economy.gd:106–107`）现在是 `broker_fee * Crew.trade_cost_factor()`，**不带参数**。要改成 `_effective_broker(port_id := "")`，与 `_effective_tariff` 对称。这是本期唯一一处函数签名变更。注意杂事（`zashi`）已经在同时压低抽解与佣金，蕃坊折扣是叠在它上面的——两者相乘后行佣最低到 `0.03 × 0.64 = 0.0192`，这正是第 9.2 节要封的口子。

### 4.3 寺院 → 仓储 + 缉私庇护

寺库（长生库）替俗人寄存货物与钱，是宋代寺院经济的常制。这是四项交付里的「仓储」。

| standing | 特权 | 插入点 |
|---|---|---|
| 20 | 寺库寄存：该港仓储 200 料 | 新 `GameState.warehouse_cap()` |
| 40 | 仓储 600 料；经卷/茶/高丽纸卖价 +6% | 同上 / `Economy.price_at_rate()` |
| 60 | 仓储 1200 料；**可雇坐地代理** | |
| 85 | 缉私系数 ×0.8（僧证作保） | `Economy.inspection_factor()`（L193–194），经 `GameState.customs_inspection()` L530 生效 |

**仓储规则**：

- 结构照抄 `Fleet.cargo`（`{good_id: {qty, cost}}`），存取都在港口页，不占船舱
- 易腐货（`goods.json` 的 `perishable`）在仓库照样按月腐坏，规则复用 `Fleet._apply_perishable()`
- **该港 `war_status` 变成 `fallen` 或 `besieged` 时，仓库全部损失**，只在月结通告里留一行
- 不收仓租（寺库的收益是香火，不是租金）

第三条是这套系统里唯一的「历史直接打到你脸上」的地方：1276 年十二月泉州降元，你囤在开元寺的货就没了，无论关系多好。这正是铁律二的实现。

## 五、坐地代理

**是什么**：一个不上船、常驻某港、替你看着关系与仓库的人。契约形式是每月付钱，不是好感度。

**如何获得**：该港任一派系 ≥60，在市舶司（牙行系）/ 蕃坊 / 寺院页上出现雇佣按钮。入伙费 = 月俸 × 12，月俸初值 **40 钱**。每港至多一人。

**不走 `Crew`**。`Crew.hired`（`Crew.gd:12`）是「每种职事至多一人」的船上职事表，`candidates_at()`（L41–51）按港口+章节+职位空缺过滤，`pay_wages()`（L145–170）欠饷三月则最高薪者去。坐地代理是**每港一人、不占职事位、不产生航海效果**，硬塞进 `Crew` 会污染 `check_symbols.py` 里已有的船员契约段。所以单开 `GameState.agents`，并把 `GameState.pay_agents()` 放在 `GameManager.advance_days()` 月结里 `Crew.pay_wages()` 的**紧邻一行**（L64–78），欠饷三月则去——规则照抄船员，玩家不用学第二套。

**驻港期间产出**（这一节是整个 P2 最危险的地方，见第九节）：

1. **维持**：该港全部派系不受月衰减、不受跳年年衰减
2. **看仓**：仓库在该港 `contested` 期间不损失（`fallen` / `besieged` 照样全损）
3. **留市**：`skip_years()` 会把**所有**港口的 `Economy.rates` 重置为 1.0（L93–134）。有代理的港口**保留自己的 rate 不重置**——「这几年他一直在开秤」
4. **跳年一次性结算**：每次跳年，每个有代理的港结一笔 `min(depth × 2, standing_max × 8)` 钱，**全局上限 6000 钱/次跳年**，与跳了几年无关

第 4 条的形式是刻意的。任何「每月 N 钱」的被动收入乘上 P1 的九年跳年（108 个月）都会变成印钞机——这与城墙无上限是同一类错误。所以结算是**一次性**、**与年数无关**、**有全局硬顶**的。

配平粗算（**推演，待实测**）：三个代理跑完 2+3+4=9 年的三次跳年，收入至多 `3 × 6000 = 18000` 钱；月俸支出 `3 × 40 × 108 = 12960` 钱。净收益约 5000 钱，相对第四章门槛 15 万钱是 3.3%。**代理不是赚钱手段，是不掉关系的手段**——这句话必须在按钮 tooltip 里写清楚，否则玩家会以为自己买了个理财产品。

## 九、防刷与防买穿

### 9.1 既有漏洞：同港买卖套利（**公式与数据已核，数值待跑**）

这不是 P2 引入的，是现在就在 `cd51729` 上的洞。四处代码逐行核过：

```gdscript
# Economy.gd:111-118 —— 定价唯一出处
var edge := Crew.interpreter_edge(port_id)
var v := base * mod * rate
if is_buy:
    return int(round(v * (1.0 + _effective_tariff(port_id)) * (1.0 - edge)))
return int(round(v * (1.0 - _effective_broker()) * (1.0 + edge)))

# Economy.gd:106-107
func _effective_broker() -> float:
    return broker_fee * Crew.trade_cost_factor()

# Crew.gd:114-115　杂事：同时压低抽解与佣金
func trade_cost_factor() -> float:
    return maxf(0.0, 1.0 - 0.12 * level_of("zashi"))

# Crew.gd:119-122　通事：只在四个异国港生效，买价降、卖价升
func interpreter_edge(port_id: String) -> float:
    if not (port_id in FOREIGN_PORTS):
        return 0.0
    return 0.07 * level_of("tongshi")
```

通事的 `edge` 是**双向**的：同一个数既压低买价又抬高卖价。同港卖价高于买价的条件是

```
(1 − 0.05·F)(1 + e) > (1 + 0.10·F)(1 − e)
其中 F = 1 − 0.12 × 杂事等级，  e = 0.07 × 通事等级
```

`data/crew.json` 实际候选（已核）：

| 职事 | 可得等级 | 最早何处何时 |
|---|---|---|
| 通事 tongshi | 1（金耽罗/耽罗/ch2/60 钱）、**2（蒲阿烈/泉州/ch1/120 钱）**、3（近藤三郎/博多/ch2/200 钱） | 第一章泉州即可雇 2 级 |
| 杂事 zashi | 1（周算筹/兴化/ch1）、**2（黄账房/泉州/ch1/120 钱）**、3（叶市舶/明州/ch2/200 钱） | 第一章泉州即可雇 2 级 |

代入解出触发门槛：

| 杂事等级 | F | 触发所需 e | 对应通事等级 |
|---|---|---|---|
| 0 | 1.00 | > 0.0732 | ≥ 2 |
| 2 | 0.76 | > 0.0559 | ≥ 1 |
| 3 | 0.64 | > 0.0472 | ≥ 1 |

**杂事本该是「省钱」的职事，实际上它把套利门槛也一起降下来了**——因为它同时缩小抽解与佣金，而这两项正是唯一阻止同港套利的价差。

净收益（同港买入立刻卖出，一轮）：

| 组合 | 最早可用 | 买价倍率 | 卖价倍率 | 每轮净收益 |
|---|---|---|---|---|
| 杂事 2 + 通事 2 | **第二章**到博多/耽罗 | 0.925 | 1.097 | **+18.5%**（实测） |
| 杂事 3 + 通事 3 | 第二章（明州+博多） | 0.841 | 1.171 | **+39.5%**（实测，原推算 39.3%） |

异国四港 `FOREIGN_PORTS = ["hakata","kagoshima","jeju","champa"]` 中博多与耽罗都是第二章解锁，所以**第二章一到博多就能用**。月俸 240 钱已核（黄账房 120 + 蒲阿烈 120，两人同在泉州第一章即可雇齐）；按 +18.5% 复利，四轮 +97%、五轮 +134%——**本金翻倍不到五轮**。

`apply_buy_impact` / `apply_sell_impact`（L229–247，`delta = amount / depth`）挡不住，反而助推：买入抬高 rate，卖出时用的是抬高后的 rate（卖得更贵），卖完 rate 再落回来。一个完整往返之后 rate 回到原点，收益却已落袋——**可无限重复**。

**现有门禁为什么没抓到**：`tools/verify_economy.py` 里所有套利断言都是**跨港**的（L113 `sell_price(dst) > buy_price(src)`、L295/L307 去程回程、L198–203 泉州→博多）。L190–195 的 `price_with_crew(pid, gid, is_buy, zashi, tongshi)` 已经把职事加成模型写好了，但**只被用来算泉州买、博多卖**，从没有人拿同一个 `pid` 代进去过。加一条同港断言只需复用这个现成函数。

**波及面（解析证明 + 实测修正）**：买卖两侧共有同一个因子 `v = base_value × ROLE_MOD × rate`，条件式两边把它约掉，所以在**实数域**上 `sell > buy` 与是哪种货、什么行情、什么身份倍率全都无关——职事凑齐则该港市面每一种货同时沦陷：

| 异国港 | 解锁 | 市面货物数 |
|---|---|---|
| 博多唐房 | ch2 | 19 |
| 耽罗 | ch2 | 12 |
| 南九州 | ch3 | 9 |
| 占城 | ch4 | 12 |
| 合计 | | **52 处（港, 货）对** |

**但价格是 `int(round(...))`，取整会破坏这个约分**。2026-09-05 实测（`same_port_check.py`，全 14 港 × 全货 × 杂事 0–3 × 通译 0–3）：

| 杂事 | 通译 | 沦陷处数 | 最肥（按比例） |
|---|---|---|---|
| 任意 | 0 | **0** | —— |
| 1 | 1 | 43 | 耽罗/高丽纸 39→40（+2.6%） |
| 2 | 1 | 45 | 博多/日本扇 29→30（+3.4%） |
| 3 | 1 | 49 | 南九州/粮 14→15（+7.1%） |
| 0–3 | **≥2** | **52（全中）** | 耽罗/海盐 8→12（**+50.0%**） |

两处修正：

1. **通译 1 级时不是全中**（43/45/49，不是 52），因为取整会把毫厘之差的价差抹平。解析证明只在实数域成立。
2. **最坏比例是 +50.0%，不是 39.3%**。取整在**便宜货**上反向放大：耽罗海盐 `base_value` 低，买 8 卖 12，四舍五入把 39.5% 撑到 50%。**按比例最坏的不是宋钱，是海盐**——这一点原稿判错了方向。

**按绝对值**看原稿的判断则完全命中：宋钱在**异国四港全都是 `consumer`**（不只博多；四港买卖价实测完全相同，`ROLE_MOD` 1.75、`v = 455` 得证），是每单位赚得最多的一档：

| 职事组合 | 买价 | 卖价 | 每单位每轮净赚 |
|---|---|---|---|
| 杂事 2 + 通事 2（第二章，泉州雇齐，240 钱/月） | 421 | 499 | **78 钱（+18.5%）** |
| 杂事 3 + 通事 3（第二章，明州+博多，400 钱/月） | 382 | 533 | **151 钱（+39.5%）** |

两行均为实测，与原稿推算逐位吻合（第二行原写 39.3%，实测 39.5%）。第二章只开博多与耽罗，实测 **31 处**立刻可用，最肥仍是耽罗宋钱。十个国内港 `edge = 0`，买价恒 `(1+T)v` 高于卖价 `(1−B)v`，安全。

而且**宋钱是违禁品，这条路却完全不过缉私**——`GameState.customs_inspection()` 只在出港时触发（`Main._on_set_sail()`，L2133–2159）。原地买卖不出港，永远查不到。

### 9.2 P2 会把这个洞从「+18.5%」撑到「+56%」

把第四节的特权按同一套公式代进去（杂事 3、通事 3、牙行 85、蕃坊 60、优先货源 −8%）：

```
抽解 T = 0.10 × 0.64（杂事3）× 0.75（牙行85） = 0.048
行佣 B = 0.03（蕃坊60）× 0.64（杂事3）        = 0.0192
买价倍率 = (1 + 0.048) × (1 − 0.21) × (1 − 0.08) = 0.762
卖价倍率 = (1 − 0.0192) × (1 + 0.21)            = 1.187
```

每轮净收益 **+55.8%**；若那件货还吃寺院 40 级的 +6% 卖价加成，到 **+65%**。（算式已复核逐位无误，但依赖尚未实现的折扣函数，属**推演**，落地后须实跑。）

**所以第一步不是加折扣，是先封洞。** 建议在 `Economy.gd` 加一条价差地板，并把 `price_at_rate` 改成在一个函数里算两侧：

```gdscript
## 同港买卖价差地板。没有它，通事的双向加成叠上坐地折扣后同港卖价会高过买价——
## 站着不动就能印钱。与城墙无上限（GameState.SIEGE_WALL_MAX）是同一类错误。
const PRICE_SPREAD_MIN := 1.08

func price_at_rate(port_id: String, good_id: String, rate: float, is_buy: bool) -> int:
    var base: float = float(_good_def(good_id).get("base_value", 0))
    var mod: float = ROLE_MOD.get(get_role(port_id, good_id), 1.0)
    var edge := Crew.interpreter_edge(port_id)
    var v := base * mod * rate
    var buy_v := v * (1.0 + _effective_tariff(port_id)) * (1.0 - edge) * (1.0 - _priority_cut(port_id, good_id))
    if is_buy:
        return int(round(buy_v))
    var sell_v := v * (1.0 - _effective_broker(port_id)) * (1.0 + edge) * (1.0 + _temple_premium(port_id, good_id))
    return int(round(minf(sell_v, buy_v / PRICE_SPREAD_MIN)))
```

一处 clamp，保证**任何**修饰组合下同港卖价至多是买价的 1/1.08。这条不靠调参维持，靠结构维持——正是城墙上限那次学到的教训。`verify_economy.py` 的 Python 镜像（L29–33 与 L190–195）要同步这个 clamp。

副作用要说清楚：博多卖青白瓷时若买价被 clamp 压住，**跨港利润会跟着掉一点**。`verify_economy.py` L203 的「满编职事使核心商路利润膨胀 < 60%」断言会往下走，方向是安全的；但 L295/L307 的「去程/回程各至少 3 种可套利货」要复跑确认没被压破。

- **P2-5 坐地代理**：`agents`、月俸、跳年维持与一次性结算上限。
- **P2-6 UI 与摘要**：两张卡、两个设施页、状态面板、跳年摘要、`standing` effects 键。

前五步玩家看不见（除了价格变了），第六步一次性把它显形。这样任何一步出问题都能单独回滚。

## 十二、不做清单

本期明确**不做**，写在这里防范围膨胀：

- **港口委托 / 任务系统**。会变成文字游戏，违铁律一；P5 年度事件才是内容的正经出口。

- **代理自动跑商 / 自动套利**。任何自动收益都是印钞机的种子。
- **standing 影响海战与守城**。守城平衡刚在 `simulate_endgame.py` 里锁死（城墙 200 上限），不碰。

- **把船屋的赊贷块搬到蕃坊页**。逻辑上更该在蕃坊，但船屋页已过门禁，本期不动。
