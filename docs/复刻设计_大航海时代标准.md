## 一、现状诊断

当前仓库是**两个互不相干的半成品缝合在一起**：

| 层 | 文件 | 规模 | 评价 |
|---|---|---|---|
| 文字 AVG | `Main.gd` + `data/scenes.json` | 581 行 / 98 场景 | 项目的灵魂，历史考据扎实 |
| 街机航海 | `WorldMap.gd` `Ship.gd` `PirateShip.gd` | 约 420 行 | 操船手感不错，但玩法是「开船打海盗捡箱子」 |

两层之间只共享 `money` 和 `cargo` 两个变量，其余状态完全隔离。

### 1.1 阻断性缺陷（不修则任何上层系统都无意义）

**① 异地差价不存在——核心循环在数学上不成立**

`Main.gd:334`：
```gdscript
sell_price = int(g.get("base_value", 20) * 1.2)
```
无论在泉州、博多还是流求卖，都是基准价的 1.2 倍。买价见 `Main.gd:234`：
```gdscript
var fluctuate = price + (price % 5)
```
`price % 5` 对固定的 `base_value` 是常数，命名叫 fluctuate 但根本不波动。

结论：玩家买入即亏，卖出必赚 20%，与去了哪里、什么时候去毫无关系。**大航海时代的全部乐趣来源在此处归零。**

**② 所有港口的市场完全一样**

`_setup_dynamic_scene`（`Main.gd:204`）拿到 `base_loc` 后只用于「离开」按钮，商品列表直接遍历全局 `goods.json`，与港口无关。泉州和博多卖同样的货、同样的价。

**③ 货物主键混乱**

`Main.gd:309` 用中文名当 key：
```gdscript
GameState.buy_goods(item_name, 1, price)   # item_name 是 "福建瓷"
```
而 `goods.json` 里有规范的 `id`（`fujian_porcelain`）。`GameState.cargo` 存的是中文名，查价时又要反向按 name 匹配（`Main.gd:332`）。任何按 id 索引的新系统接进来都会断。

**④ 市场硬截断 4 个商品**

`Main.gd:237`：`if added >= 4: break`。

**⑤ 货引逻辑自相矛盾**

衙门里「正规验引」直接 `has_customs_permit = true` 且**不收钱**（`Main.gd:259`）；而出港时无论如何都 `has_customs_permit = false` 清掉（`Main.gd:489`）。等于花钱办的引和白嫖的引没区别，且永远只能用一次。

**⑥ 没有时间**

`WorldMap.gd:16` 的 `time_of_day` 只驱动 `CanvasModulate` 的颜色，是纯灯光。航行不消耗任何日期，不存在季节。

**⑦ 没有存档。** 关掉游戏一切归零。

### 1.2 可复用的资产（不应推翻）

- **98 个剧情场景**与南宋末年的历史设定——这是项目独一无二的价值，必须保留。
- **`Ship.gd` 的操船物理**：帆档位、风向点积驱动、迎风惩罚、横摇视觉、尾迹粒子。写得比多数同类原型好，值得保留为「近距离操船/海战」场景。
- **数据驱动的场景框架**：`GameManager` + JSON 的路子是对的，只是数据模型太薄。
- **美术资产**：约 100 个 bg/icon/sprite。

## 三、目标架构

```
┌──────────────────────────────────────────────┐
│  剧情层  Narrative（现有 98 场景 + 章节推进） │
├──────────────────────────────────────────────┤
│  港口层  Port（市舶司/牙行/船屋/酒馆/寺观）   │
├──────────────────────────────────────────────┤
│  航海层  Voyage（海图 + 日推进 + 遭遇）       │
├──────────────────────────────────────────────┤
│  战术层  Combat（炮击/接舷/白刃，复用 Ship.gd）│
├──────────────────────────────────────────────┤
│  内核    Core（历法·经济·舰队·补给·存档）      │
└──────────────────────────────────────────────┘
```

内核以 autoload 单例形式提供，四个上层场景共享同一份状态。当前 `GameState` 的职责要拆开——它现在同时管钱、货、船体、蒲氏关注度，会随系统增加而失控。

拆分为：
- `Calendar`　历法与日推进
- `Economy`　港口行情与交易
- `Fleet`　舰队、船只、水手、补给
- `Chronicle`　旗标、名声、发现、声望（承接现有 `flags`）
- `SaveLoad`　存档

## 四、核心系统设计

### 4.1 历法（`Calendar`）

游戏最小时间单位为**日**。采用农历纪年以贴合南宋设定。

```gdscript
var year: int = 1260      # 景定元年
var month: int = 3
var day: int = 1
```

季节 → 季风的映射直接采用史实「**北风下南洋，南风回唐山**」：

| 农历月份 | 季风 | 有利航向 | 史实依据 |
|---|---|---|---|
| 十月～次年二月 | 东北季风（强） | 南下：泉州 → 流求 / 南洋 | 宋代海商冬季发舶 |
| 三月～四月 | 转换期（弱、多变） | 皆不利 | — |
| 五月～八月 | 西南季风（强） | 北上：南洋 → 泉州；泉州 → 博多 / 高丽 | 夏季回舶、遣日航路 |
| 九月 | 转换期 | 皆不利 | — |

这条设定会自动产生大航海时代最经典的节奏感：**去日本必须等夏季，回泉州要赶冬季**，玩家被迫围绕季节规划一整年的商路。这比随机风向有价值得多，而且完全符合项目的历史考据基调。

日推进的触发点：航行（按航段天数）、港口内行动（部分行动耗 1～3 日）、修船与补给。

### 4.2 港口经济（`Economy`）

采用大航海时代 II 的经典行情模型。每个港口对每种货物维护一条记录：

```gdscript
{
  "traded": true,        # 该港是否交易此货
  "role": "origin",      # origin 产地 / consumer 消费地 / normal 普通
  "rate": 1.0,           # 行情指数，0.4 ~ 2.2
}
```

价格公式：

```
role_mod  = { origin: 0.65, normal: 1.0, consumer: 1.75 }
买入价 = round(base_value * role_mod * rate * (1 + 抽解税率))
卖出价 = round(base_value * role_mod * rate * (1 - 牙人佣金))
```

**玩家交易冲击行情**（这是让市场有生命的关键）：
```
买入 N 单位： rate += N / market_depth      # market_depth 由港口规模决定
卖出 N 单位： rate -= N / market_depth
```
即一次性倾销会砸盘，逼玩家分港分批出货。

**每日回归**：
```
rate += (1.0 - rate) * 0.03
```
约 23 天回复一半，形成「跑一圈回来价格恢复了」的节奏。

**历史向的产地/消费地配置**（初版，可扩充）：

| 货物 | 产地（便宜） | 消费地（贵） |
|---|---|---|
| 福建瓷 / 青白瓷 | 泉州 | 博多、耽罗 |
| 香药 | 泉州蕃坊（转口） | 博多（寺社）、兴化 |
| 经卷 | 泉州、兴化 | 博多（寺社，高溢价） |
| 生丝 / 绢 | 兴化、泉州 | 博多、耽罗 |
| 硫磺 | 南岛海道、南九州 | 泉州（火药、官榷） |
| 倭铜 / 刀剑 | 博多、南九州 | 泉州 |
| 高丽参 / 皮货 | 耽罗 | 泉州 |
| 米粮 / 海盐 | 兴化 | 各港（补给品，低利润） |

泉州→博多运瓷器与经卷、博多→泉州运铜与硫磺，构成第一条完整的**往返双向盈利商路**，且必须踩着季风走。这就是第一章的核心玩法闭环。

### 4.3 货物与舱位

`goods.json` 每条补充：
```gdscript
"bulk": 1.0,        # 单位占舱（料）
"perishable": 0.0,  # 每日损耗率，香药/生鲜 > 0
"contraband": false # 是否违禁（硫磺、兵器 → 市舶司重点查扣）
```

`cargo` 结构从 `{中文名: 数量}` 改为按 id 索引并记录成本价（用于结算盈亏）：
```gdscript
cargo = { "fujian_porcelain": {"qty": 30, "avg_cost": 42} }
```

### 4.4 舰队与船种（`Fleet`）

船种取南宋东亚史实型制，以「料」为载重单位：

| 船种 | 载重(料) | 水手(最少/满编) | 耐久 | 炮位 | 备注 |
|---|---|---|---|---|---|
| 小艍船 | 200 | 6 / 15 | 120 | 0 | 起步船，近海 |
| 福船（中） | 800 | 20 / 50 | 300 | 4 | 主力商船 |
| 福船（大） | 2000 | 45 / 110 | 550 | 8 | 远洋 |
| 广船 | 1500 | 35 / 90 | 480 | 6 | 耐波，适合南洋 |
| 海鹘（战船） | 500 | 40 / 100 | 700 | 12 | 战斗特化，舱小 |

单船状态：`ship_type / 耐久 / 水手数 / 载货 / 帆桨改装等级`。
舰队为船只数组，队速取最慢一艘，总载重为各船之和。

### 4.5 补给与航行消耗

```
每日消耗：水 = 水手数 × 1，食料 = 水手数 × 1
```
- 水或食料耗尽 → 每日损失士气与水手（坏血病、逃亡）
- 士气过低 → 触发哗变事件
- 补给品在港口按当地粮价购买，兴化等产粮地便宜

这一条把「跑商赚差价」从纯套利变成有成本约束的经营，是大航海时代手感的关键来源。

### 4.6 航海层（`Voyage`）

**形态需要拍板（见第七节）。** 推荐方案：

海图上点选目的地 → 计算航段天数 → 逐日推进 → 每日按概率抽事件：

```
基础日速 = 船种基速 × 帆改装系数
风向系数 = 顺风 1.6 / 侧风 1.0 / 逆风 0.45
实际日速 = 基础日速 × 风向系数 × (士气系数)
航段天数 = ceil(航段里程 / 实际日速)
```

逐日事件表：无事（60%）、顺流加速、无风带滞留、暴风（损耗货物与耐久）、发现物线索、海盗遭遇、他船商船遭遇（可交易/打听行情）。

暴风与海盗遭遇可切入 `Ship.gd` 的实时操船场景处理——现有的操船物理在这里正好派上用场，不必废弃。

### 4.7 海战（`Combat`）

大航海时代的三阶段结构：

1. **炮击**：距离外互射，打耐久与水手
2. **接舷**：贴近后钩住，进入白刃
3. **白刃**：按水手数 × 士气 × 将领武力判定，胜方可夺船夺货

现有 `PirateShip.gd` 的 AI（转舷侧、齐射）可直接升级为炮击阶段的敌方行为。

### 4.8 人物（`npcs.json` 扩充）

酒馆可雇佣，每人带职务与技能加成：

| 职务 | 加成 |
|---|---|
| 航海士 | 日速 +、迷航率 - |
| 舵手 | 逆风效率 + |
| 会计 | 买卖价差 + |
| 炮术长 | 炮击命中 + |
| 医师 | 水手日损 - |
| 通事（译员） | 蕃坊/异国港口议价 + |

雇佣需月俸，接入每日结算。

### 4.9 发现与声望（`Chronicle`）

- 航行中触发线索 → 上陆探索 → 记入发现录
- 回泉州市舶司或朝廷「上报」→ 换取名声与赏金
- 名声累积 → 解锁港口准入、船种购买权、剧情章节

现有 `fame` 与 `discoveries.json` 在此处才真正接入玩法。

### 4.10 存档

`user://save_N.json`，序列化五个内核单例 + 剧情旗标 + 当前场景 id。港口内可存档。

## 五、与现有剧情层的融合

98 个场景不重写，改为**章节闸门**结构：

- 剧情章节推进设置旗标（现有 `flags` 机制够用）
- 旗标解锁港口准入、货物许可、船种、NPC
- 章节之间是自由沙盒期，玩家跑商攒钱攒名声
- 达到章节门槛（钱/名声/发现数/日期）触发下一章

这样「立志传」的叙事骨架与大航海时代的沙盒血肉互相支撑，而不是二选一。

### 8.2 数值（经 `tools/` 三套脚本验证后定案）

风信写成「季风转换期・风微而多变」「东北季风　利南下」「西南季风　利北上」。旅店候风把月份写在风名后面。

航海日志空卷写「未记」，损了写「卷页损了」，没题写「未题」。港口上的入口也叫航海日志。记下的一卷是日期、港口和钱数。

海图甩脱快船写成「转舵抢上风头，把那两条快船甩在了后面。绕了些路。」点验遭遇写成「点验　中途遭遇。」风涛货损写成「损折　货名」，折损数量仍按原式。

海战左栏写成「升帆　W　落帆　S　收帆 / 半帆 / 满帆」「操舵　A　D」「齐射　J　K」「弃战　B」。靠近敌船时加「接舷　G」。Esc 仍能弃战，栏上不写。船屋雇人写成「添几人」，月息写成「每百几」，帆甲加成写成「快一成二」「伤剩九成」。行会行情写成「运往某港　多多少」，呈报和修埠的名声写成「名声加」。加成比例仍是帆每级 12%、甲每级少一成伤。

市舶司职衔的抽解写成「抽解每百多少」，不再写百分号。船屋购船的水手写成「几至几」，水粮写成「水粮各多少　付多少」。船价、水手上下限和抽解倍率不动。

船籍簿章目写成「・　本钱　0 / 5000」「・　亲至　某港」，达成后记号换成「已」。进港当帧就把走过的港写进这一栏。市舶司再升一等的注用句号断开。寺观边记写成「拓「碑名」　钩子」。本钱门槛、投钱数额和拓碑一日都不动。旧边记若仍带着冒号，也算已经拓过。

分船账上的水手写成「现有 / 可载」，舱位写成「已用 / 容量 料」。开不了船时写成「水手不足　船名　水手 现有 / 至少」。现有人数、至少人数和所缺人数都不改。

旅店候风写成「掌柜掐指算了算。约多少日后风信要转。」见面册打听写成「某人压低声音说。」行情写成「某港　眼下缺某货，一件能多得　多少钱。」转向日数、风向月份和多得的钱数都不改。

船籍簿上的日期写成「宝祐三年　三月初一」。酒馆行情旁注写成「费一日」。打听仍耗一日，年月的算法不动。泉州一次可募五人，募人账条在里面滚，离开留在下面。

面板从熟漆描金改成夜潮。底是深青，线是潮光，主钮是珊瑚深字，正文是壳白。海图纸色不动。

### 10.2 为什么逆向，而不是搬过来

搬过来会把南宋海商换成法国油画、每日重置的宅子，或科幻骰子。这三部作品里能用的是决策的形状。

- Expedition 33 的材料：亮的东西只有正在做的那个决定。三张航向牌是潮玻璃，选中的那张才有潮光线。贝勒艾波克的油画、格挡战斗、法文奇幻都不进游戏。夜潮的深青、潮光、珊瑚留作这套玻璃的颜料。
- Citizen Sleeper 2 的合约卡：出发前，一张牌上同时看见去处、风、大约几日、水粮够不够。骰子身体、压力条、飞船合约都不进游戏。水粮和季风仍走 `Voyage.plan`。

### 10.3 玩法

新脚本 `scripts/core/HeadingDraft.gd`，`class_name HeadingDraft`。

池子与 `SeaChart._refresh_ports` 相同：已解锁、`depth > 0`、不是当前港。兴化与海口这种陆路点继续不进海图。

`deal(origin, salt) -> PackedStringArray`，最多三向：

1. 本章 `must_visit` 里尚未亲至、又在池子中的港，占第一席。第一章就是南岛海道北口。
2. 其余港按顺风优先、里程短者优先、`id` 次序稳定排序。
3. 从 `salt % 其余港数` 起，按顺序补满三席。其余港不够就少发，不重复，不发明港口。
4. 池子不足三港时，发出几港就是几港。

`GameState.draft_salt` 从 0 起。存档有这个字段就读，旧档没有就当 0。`SaveLoad` 版本号不动。

海图上新增「候风再发」：`draft_salt += 1`，再 `advance_days(3)`。不收旅店钱，不加名声。日志写「在船上候了三日，风又换了一手。」日子仍走现有的月息、行情回复和季风换月。同一季手里的三向会转，换月之后风的字也会变。

点海图上的港点：这一手发到了就选中；没发到就记一行「今日风不放这一向。」，不改变选中。

选定后仍走现有的 `Voyage.plan` 与 `_on_sail_pressed`。水手、水粮、货引的出港门槛留在港上的升帆，不在这一层重判。

`tools/simulate_run.py` 开局断言：这一手至多三向，南岛海道北口占第一席，盐位转一圈后泉州每个海港都会发到。跑商仍走理想港。让模拟每趟先候风再买货，这一个固定种子会在两万本钱前停住，第二章就进不去。玩家在船上可以一格一格候，规则上没有哪个港永远发不到。

### 11.3 玩法

新脚本 `scripts/core/ShoreDraft.gd`，`class_name ShoreDraft`。

`deal(facilities, salt, pin_shipyard) -> PackedStringArray`，最多三处：

1. 名单里有 `city_market`，占第一席。
2. `pin_shipyard` 为真、且名单里有 `city_shipyard`，占下一席。
3. 其余 id 按字母序，从 `salt % 其余数` 起补满三席。不重复，不发明去处。
4. 名单不足三处时，有几处发几处。

`pin_shipyard` 由港屏计算：`not Fleet.can_sail()` 或 `Fleet.supply_days() < 2`。

`GameState.shore_salt` 从 0 起。存档有这个字段就读，旧档没有就当 0。`SaveLoad` 版本号不动。

从一处回到港上，盐位不变，这一手还是原来的三扇门。

「再候一日」：`shore_salt += 1`，再 `advance_days(1)`。日志写「在岸上又候了一日，门又换了几处。」

点没开的门：日志写「今日这处没开门。」不进入。

`tools/simulate_run.py` 开局断言这套发牌，跑商仍直接买卖、直接补水粮。不把再候一日写进每一趟。

### 11.4 画面

左右两列小卡隐藏。港名匾留在上头，港湾照片露出来。三扇门铺在中栏底下，每扇最低 220×128，间距 12，潮光边 2px，半径 16。门上仍用原来的小图标和副题。船屋被钉住时，多一行珊瑚色「船还开不出去」。

没开的去处排在门下，暗边、旁注色的字，每颗最低 108×36。再下面是「看风」「再候一日」「航海日志」。看风仍是珊瑚底、深字。

### 11.5 落地顺序与对账

1. `ShoreDraft.gd` 与 `GameState.shore_salt`、存档读写。
2. `_setup_port_mode` 改成底下一排三扇门，两列小卡不再生成。
3. `simulate_run.py` 只断言发牌。
4. `check_symbols.py` 锁住「今日这处没开门。」「在岸上又候了一日，门又换了几处。」以及 `ShoreDraft`。`godot_smoke.gd` 锁住：牙行占第一席；盐位加一后第二席换门；船开不出去时船屋占第二席；盐位转一圈九处都会开。
5. 窗口点验 1280×720：三扇门和三个钮的底边在 720 以内。开着的门边像素是潮光。然后跑 `verify_economy.py` 与 `simulate_run.py`。

这一刀不打开 P7，不把 WorldMap 交回自由航行。
