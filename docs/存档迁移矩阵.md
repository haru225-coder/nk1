## 二、迁移路径逐步做了什么

| 步 | 函数 | 做的事 | 不碰 |
|---|---|---|---|
| v1→v2 | `_migrate_v1_to_v2` | state 缺键补 `GameState.from_dict` 同口径缺省（player_name=陈子龙、identity=undecided、hometown_tendency、rumors、contract_ban、news_seen、crew_history、ended）；`peak_money` 缺了按当期 money 起算 | 不碰 calendar / economy / fleet / crew；state 已有的键原样（**旗帜、发现录、钱数不动**） |
| v2→v3 | `_migrate_v2_to_v3` | state 无 `met_ids` 时按档回填「已识」（见上表 v2 行）；已有不动 | 同上，其余键原样 |
| 链外 | `_inspect` → `_check_partitions` | 迁完过结构体检（分区是对象、calendar 月日越界、economy/fleet/crew/state 数字位类型、contract_ban/rumors/contract 条目类型）——类型给坏才算坏档，字段缺省不算 | 坏档不读、不落盘 |

## 四、高危档（未支持路径的静默丢字段）

**舱位级定义「高危」= 读档成功但关键进度字段静默丢**。本次全矩阵只发现一类，且是**骨档缺分区**才发生，
已用断言钉死当前口径（判好档 + 落缺省），见 K3：

1. **v1 骨档无 fleet 分区 → 船与水粮全落缺省**（船丢、水粮 0）。
   最小失败样本：`{"version":3,"calendar":{...},"economy":{...},"crew":{...},"state":{...}}`（即 `_v1()` 删 `"fleet"` 键）。
   判定：分区整个缺席时 `_check_partitions` 只查「给了却型不对」，缺席放行；`Fleet.from_dict({})` 走缺省。
   架构上修法 = 分区缺席也判坏（那是改 `SAVE_SCHEMA` / 体检口径的拍板级改动，本片不动）；本片断言现状，
   防「静默改判坏」「谎称保住」两个方向的回退。
2. **v1 骨档无 calendar 分区 → 日期落缺省 1255-03-01**（同上腔调，边界实测列入矩阵表，未单钉断言——同族口径一条 K3 够代表）。
3. **旗号本身有两道护栏**，不算丢：①迁移不动 state 已有键；②读档经 `_harden_state` → `_normalise_flags`
   清洗（只收 true 布尔、去空名 / 去重）。**注意**：手改档里写成 `"chen_zan_stake": false` 或字串的旗会被清洗丢掉——
   这是刻意的坏档硬化（lane h1h2），不是迁移丢字段。
4. 玉湖事件标记只此一枚（`chen_zan_stake`）；`hometown_tendency` 是数字位、STATE_NUM_KEYS 体检 + v1 缺了补 0（缺省口径），
   其余「玉湖书斋 / 陈宅跑腿」不产生存档键，无迁移面。

## 五、跟门禁的接口

- 已支持路径的断言 = 本探针全部 ✓ 行；加跑档「动存档结构 / save_schema」（docs/GATES.md §一 #18、§三.18）。
- 每升一次 `SAVE_SCHEMA`：写一个 `_migrate_vN_to_vN+1`、本探针补一节该级回填、本矩阵加一行——§三.18 常见红因已有此口径。
- 坏档 / 副抄退回口径归 `save_robust_probe`（§一 #16）与 `verify_save_robustness`（§一 #8），本矩阵不重复。
- 头契约门禁 = `check_save_version_contract`（lane w21-d18，主表 lane 档、§三.19）：守 §一矩阵末行「反向迁移」那格的 `VERSION` 头注释
  （旧读档器只拒 `version > 3`；结构兼容只升 `SAVE_SCHEMA`，不兼容两者同升）——单改 `VERSION` 判红 B3、单改 `SAVE_SCHEMA` 判红 B2、
  同升判绿，跑法 `python3 tools/check_save_version_contract.py`。

## 六、异常输入（w22-h9，2026-10-03）

`tools/save_migrate_probe.gd` 末尾 `_edge_cases()` 逐类实跑（存档位 95，不碰正式位），**只钉现行为，源码未改**。本节每格都来自实跑输出（`SAVE_MIGRATE_PROBE PASS`，T 系 70 条 ✓）。

| 编号 | 输入 | 现行为 |
|---|---|---|
| T1 | 正本空文件 / 只有空白，无副抄 | `slot_source` = corrupt、`load_game` false、读档失败句「正本与副抄皆不可读。」、题签「卷页损了」；日历不被改写，文件本体不动 |
| T2 | 正本半截 JSON（写到一半 / 引号未闭）+ 副抄完好 | 退副抄：source = bak、题签与读回都是副抄 |
| T3 | 正本是合法 JSON 但顶层不是对象（数组 / 字串 / 数 / null / 布尔） | 同 T2，退副抄 |
| T4 | 字段型错：`money` 写成字串 / 对象 / 数组 / 布尔，`water` / `year` / `tariff` / `chapter` 写成字串 | 体检判坏、退副抄（`SaveLoad.STATE_NUM_KEYS` 等守着；反向变异：从 `STATE_NUM_KEYS` 删去 money → T4 money 四行红，fails=4） |
| T5 | `calendar` 缺 year / month / day 任一 | 判坏、退副抄 |
| T6 | 正本坏 + 副抄是新版所记（save_schema 超本版） | 报 future 不报卷页损：source = future、读档失败句「为新版所记，本版读不了。」 |
| T7 | 档里引用了数据表已删的 id：`last_port`、船型、`discoveries_found`、`met_ids`；日历年份出本朝范围（9990） | **照读不拦、原样读入、不提示**（体检只判型，不判 id 是否在册） |
| T8 | 正本被删只剩副抄 / 两份都删 | 只剩副抄：source = bak 可读；都删：source = none、`has_save` false、题签「未记」 |
| T9 | 同一场连存两次 | 正本逐字节一致 |
| T10 | 读档后立刻连存两次 | 第二次与第一次逐字节一致 |

结论：坏档、型错、截断、空文件、未来版本这几类都已被既有体检与副抄退回接住，本轮没有测出崩溃或静默改坏数据。T7 那类「档在、id 已不在册」照读不拦，读进去的旧 id 之后在港页 / 船队 / 发现簿上怎么显示、会不会在别处报错，本节**未测**。
