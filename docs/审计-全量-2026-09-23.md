## 结论

经济、舱位、季风、章节数据这几层是通的。三套校验全部通过，第一章到第四章按价差都没有死港。

同一条进港链上还有三处玩家能直接碰到的错：开场四屏正文不显示、旅店离开键指向不存在的港口 `city`、发现物「费 1 日」实际走两日。

## 硬伤

### 1. 流求、博多的剧情 id 盖住港口，章节晋升死锁

六个 id 同时出现在两份数据里。`quanzhou`、`xinghua`、`penghu`、`champa` 的场景 `type` 是 `port`，进港正常。`ryukyu`、`hakata` 没有 `type`，按默认剧情场景加载。

`scripts/Main.gd` 的 `load_scene` 先查 `scenes.json`，查到就不再落到 `ports.json` 的通用港口界面。入港记账只在 `type == "port"` 或港口兜底分支里调用 `_on_enter_port` → `GameState.visit_port`。剧情分支不调用。

航到流求时，`SeaChart._arrive` 把 `GameState.last_port` 设为 `ryukyu`，回港后 `start_game` 加载的就是剧情「流求海面北缘」。从这里点下去，6 步后能回到泉州港口（`ryukyu → island → return_quanzhou → ending → chapter2_letter → chapter2_accept → quanzhou`），子图里没有走不回港口的选项。人能回来，到访记录不会写上 `ryukyu`。

`data/chapters.json` 第一章 `must_visit` 是 `ryukyu`，第二章是 `hakata`。博多在第二章才解锁，而第一章条件永远不满足，所以第二条也到不了。

牙行同样进不去。模拟里开局最赚的一笔是泉州宋钱运到南岛海道北口（净赚 1191）。实机这条航次卖不掉货。

### 2. 旅店 id 没有改写成当前港口

设施按钮只改写牙行、市舶司、船屋、酒馆：

```1341:1344:scripts/Main.gd
	if target_scene in ["city_market", "city_yamen", "city_shipyard", "city_tavern"]:
		target_scene = current_scene_id + "_" + target_scene.trim_prefix("city_")
```

`city_inn` 不在这张表里。`load_scene("city_inn")` 仍因后缀 `_inn` 进入 `_setup_dynamic_scene`，港口被切成 `"city_inn".trim_suffix("_inn")` = `city`。

候风本身还会扣钱、推进日期。标题显示成「city・旅店」。离开按钮加载 `city`，两份数据都没有这个 id，先落到「区域施工中」，再靠 `GameState.last_port` 才能回到真港口。泉州、兴化、澎湖、占城以及所有通用港口的旅店都是这条路径。设计里候风是等季风的入口，导航是断的。

### 3. 开场四屏正文不进画面

`start_scene` 是 `cg_title`。这五张开场卡（`cg_title` 与四方 `cg_world_*`）把正文写在 `cg_title` / `cg_sub`，`title` 与 `body` 都是空的，也没有 `type: "title"`。

`_setup_title_mode` 才会读 `cg_title` / `cg_sub`。`load_scene` 只在 `type == "title"` 时走进去，JSON 里这个 type 的数量是 0。实际走调查模式，标题回落成「未命名地点」，正文为空。连点四次「…………」之后，`cg_narrate_table` 才有正文。游戏能往下走，卷首四屏是空的。

### 4. 「绕过去看看（费 1 日）」走了两日

`SeaChart._on_investigate_discovery` 先 `GameManager.advance_days(1)` 并把 `days_elapsed` 加 1，然后调用 `_on_event_continue`。只要还没到港，后者会再进 `_sail_next_day`，再推进一日并扣一天里程。

`advance_days` 每次都跑 `Economy.on_day_passed` 和 `Fleet.on_day_passed`。按钮文案是 1 日，水粮、士气、行情和日历走 2 日，里程只减后面那一天。

### 5. 旗舰沉没先清空货舱，结算文案仍按 25% 货损

`Ship._sink_ship` 在通知战斗失败之前调用 `Fleet.clear_cargo()`。`SeaChart._on_battle_result` 的 `lose` 分支再调用 `lose_cargo_ratio(0.25)`，此时舱已空，日志仍写「被夺去部分货物」，货名列表是空的。

单船时耐久归零，随后 `_sink` 会换成借来的小艍，结局是沉船。多船时 `damage_fleet` 只扣 `ships[0]`，其余船的耐久还在，`total_durability() > 0` 就不会进沉船保底，玩家失去全部货物，看到的却是「部分」。

`tools/simulate_run.py` 的海战段按 25% 货损记账，与这条运行时顺序不一致。校验绿，不代表战斗结算绿。

## 警告

- **剧情效果大部分没有处理器。** `apply_effects` 只认 `money`、`fame`、`days`、`flag`、`chapter`。JSON 里还有 `flag`×43、`network`×19、`merchant_credit`×18、`ledger_note`×17、`supplies`×5、`ship`×4、`cargo`×3、`discovery`×3、`sea_tendency`×2、`scholar_tendency`×2、`cargo_loss`×2。后十类写入后无读取。`days` 与 `chapter` 有处理器，JSON 里次数为 0。
- **38 个剧情旗标只写不读。** 全仓库 `has_flag` 只用于 `return_to_port`。
- **剧情里的发现物对不上 id。** `island` 的效果写的是「旧避风澳」「残裂佛碑」。发现录 id 是 `nameless_shelter_bay`、`broken_buddhist_stele`。效果键本身也没有处理器，所以不会进入 `discoveries_found`，市舶司上报拿不到这两条。航路事件那条链路（`Voyage` → `record_discovery(id)`）是通的，14 条 `near_ports` 都指向真实港口。
- **海图底图缺失。** `SeaChart.gd` 与标题模式引用 `res://assets/bg_world_map.jpg`，目录里没有这个文件，也没有对应 `.import`。`load_texture` 返回空，海图仍可绘制港口，没有底图。
- **4 个 `.png` 内容是 JPEG。** `icon_academy.png`、`icon_guild.png`、`icon_residence.png`、`icon_temple.png` 文件头为 `FF D8`。`icon_guild.png.import` 标着 `valid=false`。`GameManager.load_texture` 在 `load()` 失败后按文件头解码，行会/住处图标依赖这条兜底。本次没有在引擎里确认 `load()` 对失效 import 是返回空还是返回坏纹理。
- **市舶抽解不走杂事加成。** 买价、卖价经 `Economy.price_at_rate`，抽解乘 `Crew.trade_cost_factor()`。`GameState.customs_duty` 用裸的 `Economy.tariff_rate`。雇了杂事之后，办引花费不降。
- **人物立绘缺两张。** 酒馆 `merchant_lin` 拼出 `sprite_lin.png`，市舶司按钮 `customs_official` 不在 `npcs.json`，也没有 `sprite_customs_official.png`。`pilot_ana` → `sprite_ana.png` 存在。缺图时肖像为空，对话用回退名字，不崩溃。
- **设计文档仍停在复刻前的诊断。** `docs/复刻设计_大航海时代标准.md` 第一节把「异地差价不存在、没有存档」写成当前状态；第八节把 P2、P4 写成未做，脚本总量写成 4192 行，货物写成 27。当前脚本 5084 行，货物 29，P2 分舱与 P4 海战已在代码和校验里。第八节实测资金 25347、博多净赚 11190，与本次固定种子模拟的 28643、14461 不一致。
- **海战进行时海图的「回港」没有禁用。** `WorldMap` 用 `add_child` 叠在 `SeaChart` 上。`Ocean` 是铺到 ±20000 的 `TextureRect`，默认会吃掉鼠标，键盘战斗仍走 `_unhandled_input`。回港按钮是否还能点到，要在引擎里看一次。点到的话会直接换场景，`battle_finished` 不发出，战中已经扣掉的耐久和舱面货留在舰队上，胜负赏罚不结算。

## 对照后成立的部分

- Autoload 顺序是 GameManager → Calendar → Economy → Fleet → Crew → Voyage → GameState → SaveLoad。`_ready` 没有逆序依赖。跨文件成员引用、信号 `emit`、场景脚本路径均能对上。
- `Main.tscn` 里 `Main.gd` 的全部 `@onready` 路径都有对应节点。
- 港口 market、connections、经纬度、章节号、船种字段、职事港口与角色、发现物 `near_ports` 没有悬空 id。场景 `next` 没有指向不存在的场景或港口。
- 无船员时的定价、砸盘、季风、补给、分舱不变量与 `Fleet` / `Economy` / `Voyage` 一致。第一章到第四章每个港口都至少有一条同章盈利出港路线。
- 船员六项加成在运行时有消费点：火长日速、舵工逆风下限、总管货损、杂事抽解与佣金、通事异国价差、医人士气与减员。`simulate_run.py` 的主循环没有雇人，验的是无船员基线。
- 存档覆盖金钱、债务、名声、武力、章节、到访港口、发现录、船员、行情、舰队与历法。航行途中的剩余里程不存，存档入口在港口。

## 建议的修复顺序

1. 让入港记到港口，而不是同名剧情。剧情场景改名（例如 `ryukyu_story`），或在从海图回港时强制走 `ports.json`。修完后用一趟实航确认 `visited_ports` 含 `ryukyu`，且牙行能卖货。
2. 把 `city_inn` 加入设施改写，离开按钮回到当前港口。
3. 给开场五屏标 `type: "title"`，或把 `cg_title` / `cg_sub` 写入调查模式会读的字段。
4. 发现调查只推进一日：去掉调查里的 `advance_days`，或让「继续」在这一日不再进 `_sail_next_day`。
5. 沉船与 `lose` 结算合成一条：要么沉船不再先 `clear_cargo`、败局真扣 25%，要么文案改成全损，并让模拟器跟运行时用同一条顺序。

第 1 条不修，后面的经济打磨到不了第二章。
