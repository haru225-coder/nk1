# 市舶验引与牙行抽解（lane ea3，2026-09-27）

lane ea 待议第 6 条：市舶司验引 `GameState.customs_duty()` 按 `base_value × tariff_rate × 职衔` 收，**不含战况倍率与杂事**；牙行买价里的抽解走 `Economy._effective_tariff(port)`，含战况、站蒲家、杂事、职衔。两处不同式，是否刻意。

**结论：倍率不同是漏项；两笔都收、计税基数不同是原设计，保留。** 本 lane 已把验引税率改走 `Economy.duty_rate(port)`（＝买价抽解同一套倍率），计税基数与文案不动。

## 一、两处公式（改后）

| | 牙行买价里的抽解 | 市舶司验引（办货引） |
|---|---|---|
| 出处 | `Economy.price_at_rate` → `_effective_tariff(port)` | `GameState.customs_duty(port)` → `Economy.duty_rate(port)` |
| 何时付 | 每笔买入随价付 | 出港前一次付，一引一航次（`consume_permit`） |
| 计税基数 | 本港成交价 `base × 产地/消费地 × 行情 × 修埠` | `base_value × 舱内件数`（定额报关，不看在哪买、买多贵） |
| 税率 | `tariff_rate × 战况 × 站蒲家泉州0.8 × 杂事 × 职衔` | 同左（**改前只有 `tariff_rate × 职衔`**） |
| 其他 | 通事议价、价差地板 `PRICE_SPREAD_MIN` | 违禁货不计；地板 20 |

牙人佣金是 `broker_fee`（5%），只在卖价里扣，另是一项，不是抽解。

## 二、对照表：同一批货 50 件，泉州，行情 1.0

牙行买价按光杆（无通事、未修埠）算，价差地板不压。验引一栏写「改前 → 改后」。

| 货（base） | 泉州角色 | 牙行买价总额 | 其中抽解 | 有引·平时光杆 | 有引·杂事三级 | 有引·对峙 1276-05（×1.2） | 有引·降元 1276-12（×2.0） | 有引·降元+站蒲家（×1.6） | 有引·都保+杂事三级 |
|---|---|---|---|---|---|---|---|---|---|
| 茶叶（25） | 产地 0.65 | 900 | 81 | 125 → 125 | 125 → **80** | 125 → **150** | 125 → **250** | 125 → **200** | 95 → **61** |
| 青白瓷（90） | 产地 0.65 | 3200 | 293 | 450 → 450 | 450 → **288** | 450 → **540** | 450 → **900** | 450 → **720** | 342 → **219** |
| 象牙（220） | 普通 1.0 | 12100 | 1100 | 1100 → 1100 | 1100 → **704** | 1100 → **1320** | 1100 → **2200** | 1100 → **1760** | 836 → **535** |

「其中抽解」一栏本身也随场景变（杂事三级 ×0.64、降元 ×2.0……），与改后的验引同倍率变化。改前：买价里的抽解翻倍、打折，验引纹丝不动。

**无引**（`customs_inspection` 无引分支）三档货值一样，与货值无关：

| 场景 | 结果 |
|---|---|
| `pu_attention × 缉私倍率 ≤ 50`，钱够 | 塞 `50 + 10×违禁件数`，无违禁即 50 钱；关注 +20（+2/违禁件） |
| 同上，钱不够 | 遣返，不出港 |
| `pu_attention × 缉私倍率 > 50` | 全舱充公（茶叶 900 / 青白瓷 3200 / 象牙 12100 的货全没），另罚 `min(500, max(50, 钱×0.4))` |

有引带违禁：抽查概率 `(0.25 + 关注/400) × 缉私倍率`，查中只没收违禁货，罚 `min(300, max(50, 钱×0.4))`，货引作废。

缉私倍率（`WAR_INSPECTION`）一直接在查验上；改前只有验引税缺了战况这一半。

## 三、判定依据

1. **买价里的抽解就是市舶司的税，不是牙行佣金。** `Economy.gd` 里 `tariff_rate` 注「市舶司抽解（进口税）」，`broker_fee` 注「牙人佣金，卖出时扣」；`Main.gd` 牙行脚注注释「买价已含市舶抽解，卖价已扣牙人佣金」。所以「验引＝关税、抽解＝佣金口径」这种分工在代码里不成立。两处收的是同一个衙门的同一种税。
2. **验引收费在设计上就叫抽解。** `docs/复刻设计_大航海时代标准.md` §8.1 P0：「修复货引自相矛盾：办引按舱货抽解收费，违禁货无法报关，出港一引一航次」。界面写「按舱货抽解」，扣钱文案是「按舱货抽解 %d 钱」。两笔都收、按 `base_value` 定额，是 P0 为了让货引有价钱而刻意定的，保留。
3. **职衔：设计者两处都接了。** §8.11 职衔表「抽解」一列；`_effective_tariff` 与 `customs_duty` 都乘 `title_duty_factor()`；`tools/check_symbols.py` 专门断言「货引抽解吃职衔折让」。说明抽解的折让本意就是两处同吃。
4. **杂事：设计写「抽解与佣金 −12%/级」，审计已点名是缺口。** §8 职事表杂事一行；`docs/审计-全量-2026-09-23.md` 警告段：「市舶抽解不走杂事加成……`GameState.customs_duty` 用裸的 `Economy.tariff_rate`。雇了杂事之后，办引花费不降。」列为警告，之后没有提交解释或关闭。
5. **战况：告示对玩家承诺了，只接了一半。** `WAR_TARIFF` 注「降元港口抽解加倍；对峙期两边都要打点」；月初告示「市舶司换了旗，抽解加倍，缉私加严」。缉私一半经 `inspection_factor(last_port)` 接进了 `customs_inspection`，抽解一半没接进 `customs_duty`。`_base_tariff(port_id)` 在 `Economy.gd` 末尾「本地 main 新增函数，合并时……补回（2026-09-25）」段里，`customs_duty` 来自另一侧、不收港口参数，属于合并时漏接。泉州站蒲家的按钮写「泉州抽解永久八折」，而验引页发的正是「泉州货引」。
6. **历史提交里没有说法。** `git log -G"customs_duty|_effective_tariff|_base_tariff"` 只有 908b46f（整仓导入）与 e072e92（lane ea 价差地板，不碰验引）。没有哪次提交为两处倍率不同给过理由。

## 四、改法与影响面

改动（最小）：

- `Economy.gd`：新增公开的 `duty_rate(port_id)`，即 `_effective_tariff(port_id)`，并注明两处的分工。
- `GameState.gd`：`customs_duty(port_id := "")` 的税率改用 `Economy.duty_rate(port_id 或 last_port)`，计税基数、违禁不计、地板 20 都不变。`Main.gd` 调用点不改，缺省取 `last_port`，与出港查验同港。

影响：

- **数值**：只动验引收费。平时（loyal / besieged / closed / 无战况表）、无杂事、非站蒲家泉州的验引一文不变，也就是 1273-05 济州降元之前不雇杂事的整段开局都不变。会变的情况：杂事 1/2/3 级 ×0.88/0.76/0.64；对峙 ×1.2（泉州 1276-05 至 11）；降元 ×2.0（济州 1273-05、庆元 1276-01、温州 1276-05、福州 1276-11、泉州 1276-12 等，以 `ports.json` 的 `war` 为准）；泉州站蒲家 ×0.8。
- **买卖价**：`price_at_rate` 不动，牙行价目逐文不变。
- **文案**：一字不改。「请领 %d」与「按舱货抽解 %d 钱」显示新数。职衔账条「抽解每百 N」仍只写职衔一层，与改前相同。
- **门禁 / 探针**：`check_symbols` 的职衔断言仍成立；`verify_economy` / `simulate_run` 不模拟验引收费，不受影响；新增 `tools/qa_customs_duty_probe.gd`（6 港月 × 站蒲家 × 杂事 0–3 × 职衔两端 × 取港两路，共 193 例）。修前 182/193 红，修后 0 红。

## 待议

1. **双重抽解对玩家是否说得通。** 同一批货在牙行买入时已付抽解，出港验引再按 `base_value` 抽一次，平时两笔各约一成。牙行的设施说明写「牙人过秤开票。市舶抽解另计。」（`Main.gd` 设施说明表 `market` 条），同一页价目脚注却写「含抽解・扣佣」，两句对玩家是矛盾的。要么把买价里的一成改名（例如「市例钱」「牙契」），要么说明文案改成「买价已含抽解，出港验引另按舱货报」。文案属策划，本 lane 不动。
2. **无引的贿赂是定额。** `50 + 10×违禁`，不随货值，也不随战况。象牙满舱降元后验引 2200，塞钱 50。关注度门槛（+20/次，降元后门槛减半）能压住，但算账上逃引比改前更划算。要不要让贿赂跟 `duty_rate` 或货值挂钩，需策划定。
3. **Python 镜像不含验引。** `simulate_run.py` 的一局账和 `verify_economy.py` 的利润都不扣验引，所以 §8 的「单件利润」「净赚」偏高。要不要把验引补进模拟，另开 lane。
