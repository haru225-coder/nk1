本仓此前只有功能门禁，没有性能口径。本文记首次实测的**性能基线**与建议阈值；阈值本身**不判红、只 warn**（软档），断言由 `tools/perf_baseline.py`（lane 档，§一 表第 28 行）执行，不进一键跑。

## 3. 建议阈值（软档，默认 warn 不 fail）

`tools/perf_baseline.py` 的 `THRESHOLDS` dict 按表抄、留 ~30% 余量；探针红绿由「有 SAMPLES 帧以上即绿」管，超阈只打 `  ⚠ …`（GateReport.warn，不进必跑判词）。

| 指标 | 实测（real） | 建议阈值（软档 warn） | 余量 |
|---|---|---|---|
| 启动到可玩（real） | 1451 ms | ≤ 2000 ms | ≈ 38% |
| 帧时 p95（real） | 52 ms | ≤ 70 ms | ≈ 35% |
| 帧时 p95（synthe） | 49 ms | ≤ 70 ms | ≈ 43% |
| 峰值内存 | 109 MB | ≤ 220 MB | ≈ 100%（内存差分稳定，不必贴 30%） |
| 采样帧数下限（--secs 8） | 190 帧 | ≥ 100 帧 | 帧数随每帧时长倒数，卡住会撞下限 |
| 过阈帧（>50 ms） | real 偶见 9–11 帧（约 6%，p95 已含）、synthe 偶见 4–5 帧（约 2.5%） | 记 ⚠ 行不另设 | 本机无 GPU，真机上另议 |

50 ms 帧在 real 上偶见约 6%、synthe 约 2.5%——属本机软渲染的零工溅，不另起一格阈；真机 / GPU 环境下帧时降到正常档（≥30 fps）后本段重述。本文为软档（超阈只 `GateReport.warn`、`ok=true`），不入一键跑、不影响绿红。

### 6.4 阈值分档方案（方案、未擅改）

**本片遵 brief「给方案不擅改」**，不动 `tools/perf_baseline.py` 的 THRESHOLDS。方案供下一 lane 或本机将来静音补测定档：

- **静默档**（沿用现值 = c10 已在 956f269 落的档位）：`startup_ms ≤ 2000 / p95_ms ≤ 70 / frames_min ≥ 100 / peak_mem_mb ≤ 220`——维持现状；实测依据：c10 静默刻 real 1451 / p95 52 ×30% 余量、本片高载两跑 mem 109.4 与静默一致（内存与载量无关，§6.3）。
- **限核档**（taskset 1 核 + nice 19，新建议、本片首创一格）：本片只拿到 1 核稳态单跑样本（real startup 2679 / p95 262；synthe startup 1695 / p95 198——run1 的 real 首跑 15263 是 import 头一次带缓存、剔除不算），**样本量不够定档**，本格只写方向：**若要立限核档，先再跑一次 1 核双跑**（真实静默、不与本片的高载同步），然后按那一份的 mean ×1.35 落数字。现汇报的两数 ×1.35 只算粗示例：real startup ≈3600 / p95 ≈350，synthe startup ≈2300 / p95 ≈270。
- **高载档**（不建议立）：本片实测高载指标与静默比 ×2.2 – ×6.4 一倍带，高载环境随 20 路 lane 并发起伏、再跑一次可能又是另一组数，定时复测的复测意义不大；建议维持**现状**——高载时软档照旧只打 ⚠、靠 `frames_min ≥ 100` 兜住「探针真没起来」这个唯一的真红线。
- **落地时间点**：本片**只落文字、不改 THRESHOLDS 一个数**；限核档数字等 §6.7 cron 在真静默命中跑出来再由下一 lane 定。

## 7. （待补节）真机 / GPU 口径

本机 8 vCPU + llvmpipe（Mesa 25.0.7）软渲染是口径的下限（§0）；**真机上本表数字不可直接换用**。真机 / GPU 环境下应测：

- **GPU 侧帧时**：`FrameTiming` 的 GPU submit 端 / `OS.get_frame_delay` 细分——本机 llvmpipe 下这一项退化成 CPU 侧渲染时长，读不出独立 GPU 值；
- **显存（VRAM）占用**：本机 llvmpipe 在共享内存里跑，VRAM 只得系统内存双记，不是真实值；
- **纹理压缩格式命中**（`RD_TEXTURE_FORMATS`）：现仓 44 张 PNG 是否按 ETA2 / ASTC 预压，对真机载时差别显著，本机判断不了；
- **冷启动 shader / disk 首次装载开销**：real 冷启第 4.8 s 的大头在 `SceneTree` 加载 + `UiTheme.hook_buttons` 样式 attachment，真机上这一项才是主要差别点，本机 CPU 太重、抵不出；
- **同一姿态跨 ≥3 种 GPU 代际对照**（如 GTX 10 系 / 20 系 / Apple M 系列统一内存口径）：用于判「某天 CPU 侧照对一档值」的可换档。

当前无法测的原因：本机没接 GPU，`/dev/dri` 下只有 llvmpipe 软渲入口、没有 D3D / Vulkan 真设备可拿。**建议补测方式**：在一台装了 NVIDIA 独显或 Steam Deck 的 CI 机上跑 `python3 tools/perf_baseline.py`，把真机数字补进本节；选定机器型号与最少三代 GPU 存档后再收紧 §3 的下限 / §4 的阈档。
