## 3. 建议阈值（软档，默认 warn 不 fail）

`tools/perf_baseline.py` 的 `THRESHOLDS` dict 按表抄、留 ~30% 余量；探针红绿由「有 SAMPLES 帧以上即绿」管，超阈只打 `  ⚠ …`（GateReport.warn，不进必跑判词）。

| 指标 | 实测（real） | 建议阈值（软档 warn） | 余量 |
|---|---|---|---|
| 启动到可玩（real） | 1451 ms | ≤ 2000 ms | ≈ 38% |
| 帧时 p95（real） | 52 ms | ≤ 70 ms | ≈ 35% |
| 帧时 p95（synthe） | 49 ms | ≤ 70 ms | ≈ 43% |
| 峰值内存 | 109 MB | ≤ 220 MB | ≈ 100%（内存差分稳定，不必贴 30%） |
| 采样帧数下限（--secs 8） | 190 帧 | ≥ 100 帧 | 帧数随每帧时长倒数，卡住会撞下限 |
| 过阈帧（>50 ms） | real 偶见 9–11 帧（约 6%，p95 已含）、synthe 偶见 4–5 帧（约 2.5%） | 记 ⚠ 行不另设 | 本机无 GPU，真机上另议 |

50 ms 帧在 real 上偶见约 6%、synthe 约 2.5%——属本机软渲染的零工溅，不另起一格阈；真机 / GPU 环境下帧时降到正常档（≥30 fps）后本段重述。本文为软档（超阈只 `GateReport.warn`、`ok=true`），不入一键跑、不影响绿红。

## 5. 明显超出 50 ms 帧的现场（**只记、不改实现**）

本机并发 load 20+ 下跑 `real` 场面 p95 ≈ 374 ms（每帧十来个里有一个 ~300+ ms）——**全部帧都超过 50 ms**，但这是 CPU 供给 / llvmpipe 软渲染层面，不是游戏代码单点能单改的。具体最小修复方向（列为议，不动手）：

- 冷启动首帧挂 `Main.tscn` → `frame_post_draw` 之间 4.8 s 里大头在 `SceneTree` 加载 + `UiTheme.hook_buttons` 样式 attachment；若要把 cold-start 压进 1-2 s，可先把「主场景 `_ready` 的纯样式 hook 延迟到首帧之后」，照做只需在 `Main._ready` 里把相关三行挪到 `call_deferred`。属本 lane 范围外。
- 真机 / GPU 环境下帧时降到正常档（≥30 fps）后，本机这一套泛帧时真红真绿都说话。
