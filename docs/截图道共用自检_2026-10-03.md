## 一、真故障形态（照抄 h5 的结论）

被测场景的根 GDScript 撞上 **Parse Error** 时：

- `load(path)` **不**返回 null——`PackedScene` 壳照常装进来；
- `packed.instantiate()` **不**返回 null——根节点的 Node 壳挂出来；
- **但**根节点 `get_script() == null`、脚本字段（如 `_chart.map`、`_hand`）全是默认 nil；
- 探针裸 `add_child(inst)` 后调 `_chart.get("map")` / `move_ship_lonlat` / `_select_heading` 全落 nil，
  一路 SCRIPT ERROR，最后被外层 900 s 超时 / `probe_clock` 墙钟兜底慢红。

h5 的片内哨 ≈：load==null / instantiate==null /「挂了但 `map==null`」三种症状各自秒级 `_expect(false,…)` + `_report()` + return。共用面的难点（h5 原话）：25 支截图道每道的「关键字段」不同，「挂上了 vs 挂空了」要按道定义。

## 二、共用面（落在 `tools/shot_gate.gd`）

改法：**两段**。

```gdscript
## 同步第一段：load / instantiate / get_script 三查。返回 null == 已判红，
##   原因已 append 进 fails（带【label/症状/排查法】中文行）。
static func start_tree_probe(path: String, fails: Array = [], label := "") -> Node

## 同步第二段：入树过帧后调用方点名「必须非 null 的脚本字段」。
##   返回 true=全齐、false=有 nil（原因已 append 进 fails）。
static func check_fields(inst: Node, required: Dictionary, fails: Array, label := "") -> bool
```

**为什么要两段**——`@onready` / `_ready` 挂的字段在「未入树」时当然 nil，一体做会一律误报；
所以 `check_fields` 必须在调用方 `add_child + 过 _frames(8)` 之后才点。

调用方体例（与 `_report()` / `_expect` 一致）：

```gdscript
_chart = ShotGate.start_tree_probe(CHART_SCENE, _fails, "SeaChart 01 港名密区")
if _chart == null:
	_report()
	return
root.add_child(_chart)
await _frames(8)
if not ShotGate.check_fields(_chart,
		{"map": "SeaChart.gd 或 MapView Parse Error / MapView path 错",
		 "_hand": "SeaChart.gd 里 _hand 填表 Parse Error / path 错"},
		_fails, "SeaChart 01 港名密区"):
	_report()
	return
# 全绿才继续
```

`required` 的**键**是调用方点名的字段名（`inst.get(key)`），**值**是给后人留着排查用的中文 hint，
会嵌在错因里（`（%s）`）。
