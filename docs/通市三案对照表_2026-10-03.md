## 四、护栏重算「满编利润膨胀 < 60%」

`tools/verify_economy.py:377-388` 现式与输入口径：
```
bare = sell_price("hakata","qingbai_porcelain") − buy_price("quanzhou","qingbai_porcelain")
full = price_at("hakata",买/卖, 杂事3, 通事3) − price_at("quanzhou",买/卖, 杂事3, 通事3)
infl = (full/bare−1)×100
```
现状（P2，脚本现行实跑）：142−98 → 86→98，膨胀 +14% ✓ 绿。

三案下，同一位置、同一阈值、按各案价式重算（照抄 `/tmp/w23-a2-cases2.py` 第三段输出；算式与阈值一字未改）：

| 案 | bare | full | 膨胀 | 60% 护栏 | 输入来源 |
|---|---|---|---|---|---|
| A | 86 | 98 | +14.0% | ✓ 绿 | `price_at` 两端（脚本现式） |
| B | 86 | 88 | +2.3% | ✓ 绿 | `b_price_at`（卖=杂3 光杆；买=`_b_only` 杂0 口径） |
| C | 86 | 98 | +14.0% | ✓ 绿 | `price_at` 两端，`interp_edge` 改 0.024 |

判读：三案下护栏都绿，**护栏本身阈值不用动**；但 B 案把膨胀从 +14% 压到 +2.3%——「满编会放大收入」这一脉的
缓冲（46 点）所剩无几，与「满编月俸 > 500 才构成经营压力」相邻护栏的方向相反（后者倾向留薪酬压力来撑）。
是否要用这个缓冲换买票侧通事有效，是策划的题，本照表只把前后两个数摆出。

## 五、三案各自的代价与适用条件（不推优）

照抄自 lane ea2 收片（`/workspace/nk1-agent-briefs/lane-ea2-economy-mirror.md:74-77`）+ 本表 §一之二 / §二 / §四 数字：

- **A 维持现状**
  - 代价：2 级通事（俸 120）、3 级通事（俸 200）边际收益为零——「三级通事」名存实亡；
    杂事满级时再雇通事，异国买货的杂事折扣被地板吃回，回程反亏 2–3 文/件（倭铜 75→73、高丽参 140→137，
    见 P1 同脚本输出最后一节）。
  - 适用条件：数值上接受「1 级通事已是满性价比」，crew.json 里的 2/3 级只当剧情名头出现，不指望玩家为了数值去雇。

- **B 只压买价侧**
  - 代价：去程（卖异国）通事收益归零，回本栏全部「—」；回程才见效益（单程单件溢价 +4 ~ +10），
    满编膨胀从 +14% 掉到 +2.3%。东亚往返总体溢价幅度被压小，且杂事 3 级满级时回程「通事反亏」原样保留
    （`_b_only` 假设式把杂事 tc 全程设 0，杂事折扣既不进买卖价也不进赚赔，不赎这一口）。
  - 适用条件：愿意把「通事=去程卖贵」这条常识翻面、改成「通事=返程买便宜」；依然没解「2/3 级零边际」。

- **C 改月俸/议价率**（清单就把「月俸压平 60」与「edge 降 0.024」写成或，本文一并摆出）
  - 代价：动一个运行时系数（`scripts/core/Crew.gd:133` 的 0.07 → 0.024）或动 `data/crew.json` 三行月俸；
    前者有「现有光杆卖倍率乘以 1+3×0.024=1.017 < 封顶 1.0185 → 3 级才触顶」的读者钩子，
    后者把 2/3 级月俸压到 60，低级通事直接被信用说破产（除非一并改簿记口径）。
    两案镜像脚本/断言都要同步重录：未满 60 护栏的 14% 会动、账全要重记。
  - 适用条件：愿意接受「3 级才触顶」的边际曲线，或者接受「通事三级月俸都一样约 60」的商业逻辑。
